<h1 align="center">Twitch Miner</h1>

<p align="center">
  <strong>Minează Twitch Drops, insigne și puncte de canal pe câte conturi vrei, fără browser și fără vreo filă Twitch deschisă.</strong>
</p>

<p align="center">
  O aplicație desktop pentru Linux, Windows și macOS sau o imagine Docker cu același panou web, de rulat pe un server de acasă sau pe un Raspberry Pi. Fiecare cont folosește în jur de 3 MB de memorie și aproape deloc procesor.
</p>

| **Server Linux** · x86-64 sau ARM64 | Doar serverul, fără Docker ([x86-64](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner-server_linux_x64) sau [ARM64](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner-server_linux_arm64)): vezi [Fără Docker](#systemd) |

Pe Linux poți instala și dintr-un terminal. Pe ARM64, înlocuiește `x64` cu `arm64` în
comenzi.

Debian, Ubuntu, Raspberry Pi OS:

```bash
curl -LO https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.deb
sudo apt install ./twitch-miner_linux_x64.deb
```

Fedora, openSUSE:

```bash
curl -LO https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.rpm
sudo dnf install ./twitch-miner_linux_x64.rpm
# openSUSE: sudo zypper install ./twitch-miner_linux_x64.rpm
```

AppImage, pe orice distribuție:

```bash
curl -LO https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.AppImage
chmod +x twitch-miner_linux_x64.AppImage
./twitch-miner_linux_x64.AppImage
```

Aceleași comenzi actualizează o instalare existentă: numele fișierelor nu se schimbă.

Versiunea pentru macOS nu este notarizată. Prima dată, deschide aplicația: macOS o
blochează. Apoi mergi la **Configurări sistem › Intimitate și securitate** și fă clic pe
**Deschide oricum**.

Actualizările sunt semnate. Aplicația verifică la pornire dacă există o versiune nouă, apoi
la fiecare oră (frecvența o poți schimba în **Setări › Despre**). Nu instalează niciodată
singură o versiune: o instalezi tu cu un singur clic, din mesajul care apare sau din
**Setări › Despre**.

Datele se află în dosarul de date al utilizatorului:

- Linux: `~/.local/share/twitch-miner`
- Windows: `%APPDATA%\twitch-miner`
- macOS: `~/Library/Application Support/twitch-miner`

## <a name="features"></a>Funcționalități

### Conturi și streameri

- **Oricâte conturi într-o singură aplicație.** Fiecare cont minează independent, în
  propriul mod: **Drops și puncte** (un canal pentru cea mai bună campanie, celălalt pentru
  streamerii tăi), **Doar Drops** sau **Doar puncte**.

  <img src="../media/ro/accounts-mining.avif" alt="Mai multe conturi care minează în același timp, pe pagina Acasă">

- **Un asistent pentru fiecare cont nou.** După autentificare, pornește de la setările
  implicite sau de la cele ale altui cont. Alege modul, campaniile și streamerii, apoi
  „Începe minarea” sau „Salvează și pornește mai târziu”.

  <img src="../media/ro/account-setup.avif" alt="Asistentul de configurare al unui cont nou, pas cu pas">

- **O modificare aplicată altor conturi dintr-un clic.** După ce schimbi ceva la un cont,
  mesajul de confirmare îți oferă „Aplică la alte conturi”. Modificarea se repetă pe
  conturile bifate, care își păstrează restul setărilor.

  <img src="../media/ro/apply-to-accounts.avif" alt="O modificare repetată pe alte conturi cu „Aplică la alte conturi”">

- **Adaugă un streamer.** Pornește imediat cu opțiunile implicite: cele ale aplicației sau
  cele alese de tine pentru acest cont. Ajustează-le pe loc, dacă e nevoie: cufere bonus,
  raiduri, momente, serie de vizionare, chat, predicții.

  <img src="../media/ro/streamer-add.avif" alt="Un streamer adăugat prin căutarea Twitch, apoi opțiunile lui">

- **Editează un streamer.** „Editează” îi deschide opțiunile: cufere bonus, raiduri,
  momente, serie de vizionare, chat, predicții… Un comutator îl activează sau îl
  dezactivează fără să-l scoată din listă.

  <img src="../media/ro/streamer-edit.avif" alt="Opțiunile unui streamer, deschise din rândul lui">

- **Editează mai mulți streameri deodată.** Bifează-i, apoi „Editează cei N streameri
  selectați”. Se aplică doar opțiunile pe care le schimbi. O opțiune care diferă între ei
  apare ca „Mixt”, iar comutatorul ei devine două butoane, „Da” și „Nu”. Apoi aplicația îți
  propune să le faci opțiunile implicite pentru streamerii noi.

  <img src="../media/ro/streamers-group-edit.avif" alt="Editarea mai multor streameri, cu opțiuni „Mixt”">

- **Importă streameri.** Lipește o listă (până la 500 de nume) sau refolosește lista altui
  cont ori canalele pe care le urmărește contul. Lista este verificată, ca să fie adăugate
  doar canale care există.
  Actualizările în direct acoperă 46 de streameri pe cont: următorii din listă nu primesc
  raiduri, momente sau predicții.

  <img src="../media/ro/streamers-import.avif" alt="Importul de streameri: o listă lipită, alt cont, canalele urmărite">

- **Spam Points.** Revendică o recompensă personalizată a unui canal de mai multe ori la
  rând. Alege un canal din lista ta de Puncte sau orice canal găsit prin căutarea Twitch:
  recompensele lui apar împreună cu soldul contului, citit în timp real. Setează cantitatea
  (până la 25, în limita soldului), apoi „Revendică”. Rezultatul apare la sfârșitul seriei,
  iar fiecare serie are rândul ei în Jurnal.

  <img src="../media/ro/spam-points.avif" alt="Spam Points: un canal ales, 10 × o recompensă cu mesaj revendicată, revendicările apar în chatul Twitch al canalului, apoi rândul din Jurnal">

### Drops

- **Toate campaniile Drops în desfășurare.** Fiecare campanie are fișa ei: recompense,
  conectarea contului de editor, „Minează cu prioritate”. Lista vine de la proiectul
  [Drops Alerts](https://dropsalerts.com) și se reîmprospătează la fiecare 5 minute.

  <img src="../media/ro/drops-catalogue.avif" alt="Catalogul sub formă de calendar, căutarea și fișa unei campanii">

- **Ordinea ta de minare.** Trage campaniile în ordinea dorită. Cele noi își găsesc singure
  locul: întâi categoriile tale prioritare, apoi cele care se termină mai devreme sau cărora
  le-au rămas cele mai puține minute. Exclude categorii, cuvinte, o campanie sau o singură
  recompensă și sari peste campaniile care nu se pot termina la timp. „Minează cu
  prioritate”, în fișa unei campanii, o pune pe primul loc.

  <img src="../media/ro/drops-order.avif" alt="Ordinea de minare, categoriile prioritare și excluderile">

- **Inventar și „Revendică tot”.** Pagina Inventar împarte recompensele în „De revendicat”,
  „În desfășurare” și „Revendicate”. Revendică-le pe rând, pe toate odată sau activează
  „Revendică drops automat”.
  După „Conectează contul de editor”, contul este citit din nou imediat ce revii în
  aplicație, așa că legătura apare pe loc.

  <img src="../media/ro/drops-inventory.avif" alt="Inventarul și butonul „Revendică tot”">

- **„Streamerii mei mai întâi pentru Drops și insigne”.** Pentru campania curentă, un streamer din
  lista ta al cărui live contează pentru acea campanie trece înaintea celorlalte canale.
  Același canal avansează drop-ul și îți aduce punctele lui de canal. Activat implicit.

  <img src="../media/ro/drops-streamers-first.avif" alt="Un streamer din listă, urmărit pentru Drops și pentru punctele lui">

- **Prioritatea recompenselor.** Când două campanii au același rang, minerul o alege întâi
  pe cea ale cărei recompense se potrivesc tipului preferat (insignă, emote, obiect din
  joc). Nu îți depășește niciodată ordinea de minare.

- **Insigne (beta).** Pagina Insigne listează toate insignele globale din chatul Twitch și
  cum le obții. Fiecare cont are propria pagină Insigne: insignele în desfășurare cu
  progresul lor, cele pe care le mai poate obține și cele pe care le are. Minerul țintește
  insignele din campaniile Drops și misiunile Twitch și le sare pe cele pe care contul le
  are deja. O insignă de urmărit în fiecare zi este minată din nou în fiecare zi, până la
  ultima („20 min. pe zi, 3 zile”), iar un canal din oricare dintre categoriile campaniei
  contează. Un cufăr dă „1 insignă la întâmplare din N”. O insignă care cere un abonament
  este minată după ce te-ai abonat sau ai oferit un abonament cadou în timpul campaniei,
  pe un canal din categorie, și Twitch îl numără. Un abonament deja activ, un abonament
  Prime sau o reînnoire nu contează. Nimic nu este minat înainte de începutul campaniei.
  În „Ce să se mineze, în ordine”, trage categoriile prioritare, insignele și celelalte
  campanii Drops în ordinea dorită sau dezactivează una dintre ele. O misiune Twitch este
  minată doar pe un canal unde Twitch o oferă în panoul său Drops. O evoluție (Pichu →
  Pikachu) este minată imediat ce contul are insigna din care evoluează: minerul își pune
  singur acea insignă chiar înainte și nu o mai pune la loc pe cea veche; „Minează
  evoluțiile insignelor”, în setările de insigne ale contului, dezactivează asta. Un clic
  pe o insignă îi deschide detaliile: cerința completă, toate categoriile și canalele,
  colecția, evoluția și progresul fiecărui cont. Această funcție este în beta.

  <img src="../media/ro/badges.avif" alt="Pagina Insigne, insignele unui cont, apoi „Ce să se mineze, în ordine” cu Insigne trase primele">

### Monitorizare

- **Un jurnal pentru tot și fiecare cerere.** Jurnalul păstrează fiecare eveniment: drops,
  puncte câștigate și cheltuite, cufere, pariuri, raiduri, live-uri care încep…
  Filtrează-l după cont, după filă (Drops, Insigne, Puncte, Altele) și după tip.
  **Loguri tehnice › Cereri** listează fiecare cerere trimisă către Twitch și către alte
  servicii, cu rezultatul și durata ei. Logurile și cererile nu conțin niciun token sau
  secret: „Copiază pentru un raport de eroare” le copiază, gata de lipit într-un raport de
  eroare pe [GitHub](https://github.com/SunkwiBOT/twitch-miner/issues) sau
  [Discord](https://discord.gg/support-bots-891685895781113886).

  <img src="../media/ro/journal-requests.avif" alt="Jurnalul filtrat, apoi Loguri tehnice › Cereri">

- **O pagină Statistici.** Puncte câștigate, drops revendicate, timp de vizionare și
  predicții câștigate în ultimele 7, 30 sau 90 de zile, cu cel mai bun streamer sau cea mai
  bună categorie în spatele fiecărei cifre. O curbă a punctelor per streamer arată soldul
  în timp, cu marcaje pentru serii, raiduri, momente și predicții și un indiciu la fiecare.

  <img src="../media/ro/stats.avif" alt="Plăcile paginii Statistici pe 30 de zile, apoi curba de puncte a unui streamer cu un marcaj">

- **Pauză și pauză zilnică.** Un singur buton de pauză, pentru un cont sau pentru toate:
  pauză până reiei, sau pentru 30 de minute, 1 oră, 4 ore, până mâine la 09:00, sau o dată
  și oră personalizate; cât timp e în pauză, același buton scrie „Reia”. O insignă arată
  ora la care se termină o pauză cu durată, iar fiecare cont din bara laterală își arată
  starea: rulează, în pauză sau o problemă de verificat. O pauză zilnică oprește minarea
  tuturor conturilor în fiecare zi între două ore, în fusul orar ales, și o reia după ce
  se termină, cu propria insignă în bara de sus.
- **Export CSV și numărători pe categorie.** Jurnalul exportă drops revendicate ca fișier
  CSV (data, contul, categoria, campania, drop, minute), filtrate după cont, iar o
  fereastră de dialog arată câte drops au fost revendicate în fiecare categorie. Aplicația
  desktop salvează fișierul printr-o fereastră de salvare; panoul web îl descarcă.

### Pe desktop sau pe un server

- **Aceeași interfață peste tot.** Aplicația desktop (Linux, Windows, macOS) și imaginea
  Docker afișează același panou. Docker rulează pe un VPS, un NAS sau un Raspberry Pi, fără
  ecran și fără browser pe acea mașină: panoul se deschide în orice browser.
  Pe telefon, panoul se adaptează la ecran și, prin HTTPS, se instalează ca o aplicație.
- **Consum redus.** În jur de 3 MB de memorie pe cont, aproape deloc procesor și
  o imagine Docker de circa 12 MB.

### Securitate și actualizări

- **Sesiunile tale, protejate.** Fără parola Twitch: te autentifici pe
  `twitch.tv/activate`, din browserul tău. Sesiunile sunt criptate pe disc și le poți
  revoca din [setările Twitch](https://www.twitch.tv/settings/connections). Pe desktop, o
  parolă opțională a aplicației o blochează: nu se minează nimic până nu este introdusă. Cu
  Docker, panoul are propria parolă, se blochează singur după câteva minute de inactivitate
  și funcționează prin HTTPS în spatele unui proxy. Cinci parole greșite la rând blochează
  adresa IP timp de 30 de secunde.

  <img src="../media/ro/security-lock.avif" alt="Lacătul: aplicația blocată, apoi deblocată cu parola ei">

- **Actualizări semnate, niciodată automate.** În bara de sus apare o insignă „Actualizare”
  cu numărul versiunii, iar o notificare de pe desktop te anunță și ea, activă implicit
  (un comutator din **Setări › Notificări** o dezactivează; într-un browser, dă clic pe
  „Permite” când întreabă). „Instalează și repornește” cere întâi o confirmare, apoi
  aplicația instalează versiunea și repornește. Dacă are o parolă a aplicației,
  repornește blocată: introdu-o din nou ca să reiei minarea. Se instalează doar o
  versiune semnată de proiect. Și panoul Docker, și binarul systemd te anunță, cu
  comenzile de rulat.

  <img src="../media/ro/updates.avif" alt="Insigna „Actualizare”, confirmarea, apoi instalarea">

### Și în plus

- Ca alte instrumente de minare: cufere bonus, raiduri, momente, obiective ale comunității,
  predicții (strategii, momentul pariului, condiții), prioritate pentru seriile de
  vizionare și pentru canalele cu abonament, prezență în chat (se poate dezactiva), opțiuni
  implicite pentru streamerii noi, notificări Discord, Telegram și webhook cu imagini și
  un buton „Testează” pentru fiecare (pe
  server, limba lor se alege în **Setări › Notificări**), proxy global sau per cont.
- 29 de limbi, teme întunecată și luminoasă, notificări desktop, pictogramă în bara de
  sistem, pornire odată cu sistemul.

  <img src="../media/ro/basics.avif" alt="Limbi, temele luminoasă și întunecată, o notificare desktop și pictograma din bara de sistem">

- **Adăugarea conturilor prin lipirea unei liste de tokenuri.** Ești deja conectat în altă parte? Lipește o listă de tokenuri de acces, câte unul pe linie (până la 50); fiecare este verificat în timp real, cu un contor „Verificate: n/N” și reîncercare pentru fiecare linie eșuată, apoi un singur pas de setări se aplică întregului lot. Importul în sine rulează în fundal, cu progres în timp real pe fiecare cont, poate fi anulat pe parcurs, iar o reîncercare ulterioară retrimite doar conturile care au eșuat. Eliminarea unui cont importat astfel oferă și revocarea tokenului pe Twitch.

> [!WARNING]
> Acest proiect nu este afiliat cu Twitch. Automatizarea unui cont poate încălca termenii
> Twitch sau regulile unei campanii.

## <a name="docker"></a>Docker

Serverul afișează același panou într-un browser. Imaginea este
`ghcr.io/sunkwibot/twitch-miner`, pentru `amd64` și `arm64`. Când apare o
versiune nouă, panoul te anunță: `docker compose pull`, apoi `docker compose up -d`.

```yaml
services:
  miner:
    image: ghcr.io/sunkwibot/twitch-miner:latest
    pull_policy: always   # descarcă cea mai nouă imagine la fiecare pornire
    restart: unless-stopped
    ports: ["8080:8080"]   # în spatele unui reverse proxy HTTPS: de eliminat, sau "127.0.0.1:8080:8080"
    environment:
      MINER_PASSWORD: "change-me"   # obligatorie, cel puțin 12 caractere
      # MINER_PUBLIC_URL: "https://miner.example.com"   # doar în spatele unui reverse proxy HTTPS
    volumes:
      - miner-data:/data

volumes:
  miner-data:
```

```bash
docker compose up -d
```

Deschide <http://localhost:8080> (sau adresa mașinii în rețeaua ta) și introdu parola.

### Variabile

| Variabilă | Implicit | Rol |
|---|---|---|
| `MINER_PASSWORD` | niciuna | Parola panoului, obligatorie: fără ea, serverul refuză să pornească. De cel puțin 12 caractere (una mai scurtă afișează un avertisment la pornire). Valoarea de exemplu `change-me` este refuzată. |
| `MINER_PASSWORD_FILE` | niciuna | Citește `MINER_PASSWORD` dintr-un fișier, de exemplu un secret Docker. Una sau alta, nu amândouă. |
| `MINER_PUBLIC_URL` | niciuna | Doar în spatele unui reverse proxy HTTPS (Caddy, nginx, Traefik, Cloudflare Tunnel…): adresa `https://` a panoului, fără cale, de exemplu `https://miner.example.com`. Proxy-ul trebuie să transmită `X-Forwarded-Proto`, `X-Forwarded-For` și websocketurile, ceea ce proxy-urile obișnuite fac implicit, iar portul containerului nu trebuie să fie accesibil direct. Panoul refuză atunci tot ce nu vine prin proxy, prin HTTPS, și blochează o adresă timp de 30 de secunde după 5 parole greșite. Proxy-ul trebuie să ruleze pe aceeași mașină sau în rețeaua ei locală: o conexiune de la o adresă publică este refuzată. |
| `MINER_TRUSTED_HOPS` | `1` | Doar cu `MINER_PUBLIC_URL`: câte proxy-uri adaugă o intrare în `X-Forwarded-For`, de la 1 la 10. `2` cu două proxy-uri unul în spatele celuilalt, de exemplu Cloudflare în fața Traefik. |
| `MINER_PROXY_NETWORKS` | niciuna | Doar cu `MINER_PUBLIC_URL`: rețelele din care se conectează proxy-ul, separate prin virgule, spații sau linii noi: o singură adresă sau o rețea ca `192.168.1.0/24` ori `2001:db8:1::/64`. Odată setată, proxy-ul este acceptat doar de la adresa de loopback și din aceste rețele, nu și din toată rețeaua locală privată. O valoare goală, `/0` sau o rețea cu biți de gazdă setați opresc pornirea doar când este setat și `MINER_AUTH_HEADER`; fără el, sunt acceptate cu un avertisment. |
| `MINER_AUTH_HEADER` | niciuna | Forward auth / SSO: numele unui antet pe care proxy-ul îl setează pentru utilizatorul autentificat: `Remote-User` pentru Authelia, `X-authentik-username` pentru Authentik, `X-Auth-Request-User` pentru oauth2-proxy (cu `--set-xauthrequest`). O cerere admisă prin proxy — de la o adresă din `MINER_PROXY_NETWORKS`, cu un `Host` care corespunde cu `MINER_PUBLIC_URL` — cu o singură linie nevidă în acel antet se autentifică fără `MINER_PASSWORD`. Necesită `MINER_PUBLIC_URL` și o `MINER_PROXY_NETWORKS` setată explicit; loopback singur nu este niciodată suficient pentru asta. Refuză un antet pe care proxy-ul, un browser sau un client îl scrie deja (`X-Forwarded-*`, `Host`, `Cookie`, `Authorization`, `X-Real-IP`, `Forwarded`, `Via`, `User-Agent`, `Accept*`, `Sec-Fetch-*`, `Cache-Control`, `CF-Connecting-IP`, `Priority`, `Connection`, `Origin`, `Referer`, `X-Request-Id`, `Content-Type`…). |
| `MINER_AUTH_USERS` | niciuna | Doar cu `MINER_AUTH_HEADER`: valorile antetului cărora li se permite autentificarea, separate prin virgule, spații sau linii noi, ca și `MINER_PROXY_NETWORKS`. Potrivirea ține cont de majuscule. O valoare setată, dar goală este refuzată, la fel ca o `MINER_PROXY_NETWORKS` goală cu antetul setat. Fără ea, orice valoare setată de proxy se autentifică — fiecare utilizator SSO autentificat devine admin — iar serverul avertizează despre asta la pornire; cu ea, serverul afișează la pornire numărul de valori recunoscute. |
| `MINER_VAULT_PASSPHRASE` | niciuna | Doar pentru un dosar de date copiat din aplicația desktop care are o parolă a aplicației: îl deblochează la pornire. Un server creat de la zero nu are niciodată nevoie de ea. |
| `MINER_VAULT_PASSPHRASE_FILE` | niciuna | Citește `MINER_VAULT_PASSPHRASE` dintr-un fișier. Una sau alta, nu amândouă. |
| `DATA_DIR` | `/data` în imagine, altfel `data` în directorul de lucru | Baza de date, fișierul cu cheia și logurile. |
| `LOG_DIR` | `$DATA_DIR/logs` | Fișierele de log: câte unul pe zi, se păstrează ultimele 14. |
| `HOST` / `PORT` | `0.0.0.0` / `8080` | Adresa de ascultare: o adresă IP și un port de la 1 la 65535. |
| `RUST_LOG` | `info,hyper=warn,reqwest=warn` | Nivelul de logare. |

Serverul citește și verifică variabilele o singură dată, la pornire. O valoare invalidă
oprește serverul cu un mesaj, în loc să treacă tacit la o valoare de rezervă.

În spatele unui proxy invers, setează `MINER_PUBLIC_URL`: fără ea, prima cerere care vine
printr-un proxy scrie un avertisment în loguri, pentru că încercările de conectare sunt
atunci numărate pe adresa proxy-ului, iar parolele greșite ale unui vizitator i-ar bloca
pe toți. Conexiunea live trimite un ping la fiecare 30 de secunde, ca un proxy să nu o
închidă când nu se întâmplă nimic. Când Twitch sau rețeaua cad, serverul răspunde `424`,
niciodată `502` sau `504`: în spatele Cloudflare, vezi eroarea reală în locul paginii
Cloudflare.

#### Autentificare printr-un proxy de încredere (forward auth / SSO)

_Disponibil începând cu v1.16.0._

Cu o singură autentificare în fața mai multor aplicații self-hosted (Authelia, Authentik,
oauth2-proxy…), `MINER_AUTH_HEADER` sare peste parola proprie a panoului: autentificarea
la proxy este suficientă. Setează și `MINER_AUTH_USERS` cu valorile permise, altfel orice
utilizator SSO se autentifică drept admin. `MINER_PASSWORD` continuă să funcționeze
pentru scripturile care se autentifică direct prin `POST /api/auth`, niciodată printr-un
browser: router-ul de mai jos trimite orice altă cerere prin `forwardAuth`, deci un
browser care vizitează panoul are mereu nevoie de SSO pornit mai întâi. Un al doilea
router acționează doar pe `POST` și `DELETE` pe `/api/auth` — autentificarea și
deconectarea cu parola — și golește el însuși antetul, în loc să elimine `forwardAuth`:
lărgirea acestei reguli dincolo de acea singură cale ar lăsa să treacă și un antet
falsificat de client.

Proxy-ul trebuie să păstreze `Host`-ul original al cererii neschimbat pe drumul spre
miner, altfel `MINER_PUBLIC_URL` nu se potrivește niciodată cu el, iar antetul este
ignorat tacit, cu un avertisment în loguri la prima apariție: nginx are nevoie de
`proxy_set_header Host $host;`, Apache are nevoie de `ProxyPreserveHost On`. Traefik și
Caddy îl păstrează neschimbat implicit, nimic de adăugat pentru niciunul dintre ele.

Niciunul dintre aceste produse nu elimină un antet trimis chiar de client: fiecare rută
de la proxy la miner are nevoie de propria regulă care să îl suprascrie (`forwardAuth`
din Traefik șterge doar anteturile listate în `authResponseHeaders` și retransmite
nemodificat orice alt antet al clientului). Rulează proxy-ul și miner-ul singure, într-o
rețea doar a lor, cu o adresă statică pentru proxy, și nu publica niciodată portul
miner-ului: orice altceva care îl atinge — alt container, un proces de pe gazdă — ar
putea seta singur antetul.

Authelia în spatele Traefik, cele două singure pe `miner-net`, retransmițând
utilizatorul autentificat în `Remote-User`:

```yaml
networks:
  edge: {}          # Traefik și Authelia comunică aici
  miner-net:        # doar Traefik și miner-ul sunt în această rețea
    ipam:
      config:
        - subnet: 10.10.0.0/29

services:
  traefik:
    # configurația ta obișnuită de Traefik: entrypoints, alte rețele, alte aplicații
    networks:
      edge: {}
      miner-net:
        ipv4_address: 10.10.0.2

  authelia:
    # configurația ta obișnuită de Authelia
    networks:
      edge: {}
    labels:
      traefik.http.middlewares.authelia.forwardAuth.address: "http://authelia:9091/api/authz/forward-auth"
      traefik.http.middlewares.authelia.forwardAuth.trustForwardHeader: "true"
      traefik.http.middlewares.authelia.forwardAuth.authResponseHeaders: "Remote-User"
      # pentru router-ul scripturilor de mai jos: golește Remote-User în loc să
      # sară peste autentificare, astfel un antet falsificat de client tot nu funcționează nici pe acea rută
      traefik.http.middlewares.blank-remote-user.headers.customrequestheaders.Remote-User: ""

  miner:
    image: ghcr.io/sunkwibot/twitch-miner:latest
    networks:
      miner-net:
        ipv4_address: 10.10.0.3   # tot statică: o adresă aleasă aleatoriu ar putea coincide
    # fără "ports": această rețea ajunge doar la Traefik, de la 10.10.0.2
    environment:
      MINER_PASSWORD: "change-me"
      MINER_PUBLIC_URL: "https://miner.example.com"
      MINER_PROXY_NETWORKS: "10.10.0.2"
      MINER_AUTH_HEADER: "Remote-User"
      MINER_AUTH_USERS: "alice,bob"
    volumes:
      - miner-data:/data
    labels:
      traefik.http.routers.miner.rule: "Host(`miner.example.com`)"
      traefik.http.routers.miner.middlewares: "authelia@docker" # repetă pe fiecare router către miner
      # pentru scripturi, cu MINER_PASSWORD: ocolește Authelia, dar nu golirea antetului
      traefik.http.routers.miner-api.rule: "Host(`miner.example.com`) && Path(`/api/auth`) && (Method(`POST`) || Method(`DELETE`))"
      traefik.http.routers.miner-api.middlewares: "blank-remote-user@docker"

volumes:
  miner-data:
```

#### Întărirea unui alt proxy

Niciunul dintre aceste produse nu elimină singur o copie a antetului trimisă de client:
adaugă linia de eliminare de mai jos înaintea directivei care îl setează din răspunsul
SSO, pe fiecare rută către miner, inclusiv cea a scripturilor. Traefik, Caddy, nginx,
Apache și HAProxy de mai jos au fost fiecare verificate pe o instanță reală care
termină TLS, cu un antet falsificat, unul duplicat și o variantă de majuscule sau
liniuță joasă; Cloudflare Tunnel și Tailscale Serve provin din documentația și codul
lor sursă, netestate independent aici.

- **nginx**: `auth_request` doar validează, nu atinge niciodată singur anteturile —
  o configurație care îl apelează dar nu setează niciodată singură `Remote-User`
  retransmite linia clientului neschimbată (dovedit: un `Remote-User: admin`
  falsificat a ajuns la miner literalmente fără următoarele două linii). Adaugă
  mereu `auth_request_set $auth_user $upstream_http_remote_user;` apoi
  `proxy_set_header Remote-User $auth_user;`, care îl suprascrie — niciodată
  opțional. De asemenea `proxy_set_header Host $host;`, sau `$http_host` dacă
  `MINER_PUBLIC_URL` indică un port neobișnuit (`$host` elimină portul, iar
  antetul nu mai este niciodată de încredere în tăcere). nginx mai aruncă și orice
  antet al cărui nume conține o liniuță joasă, cu excepția cazului în care
  `underscores_in_headers on;` este setat; de aceea `MINER_AUTH_HEADER` refuză un
  astfel de nume.
- **Caddy**: `forward_auth` cu `copy_headers Remote-User` deja suprascrie singur o
  copie de la client, dovedit, nimic altceva nu e necesar. `request_header
  -Remote-User` chiar înainte este o apărare în adâncime suplimentară inofensivă,
  nu o cerință, spre deosebire de Traefik, unde un al doilea router care sare
  complet peste `forwardAuth` are într-adevăr nevoie de golirea explicită.
- **Apache**: `RequestHeader unset Remote-User` necondiționat, apoi
  `RequestHeader set Remote-User "…" env=AUTH_OK` pe baza a ceea ce validează
  sesiunea, și `ProxyPreserveHost On` pentru aceeași cerință de `Host` de mai sus.
- **HAProxy**: `http-request del-header Remote-User` necondiționat, apoi
  `http-request set-header Remote-User alice if <acl-sesiune-validă>`. HAProxy nici
  nu atinge singur `X-Forwarded-For`: adaugă
  `http-request set-header X-Forwarded-For %[src]`, altfel o valoare falsificată
  ajunge la miner neschimbată.
- **Cloudflare Tunnel**: lasă `httpHostHeader` nesetat (implicit retransmite deja
  `Host`-ul public cerut de client); este un tunel, nu un proxy care curăță anteturi,
  așa că asociază-l cu unul dintre proxy-urile de mai sus pentru `MINER_AUTH_HEADER`,
  în loc să te bazezi doar pe el.
- **Tailscale Serve**: `Tailscale-User-Login`. `tailscaled` elimină deja orice copie
  trimisă de client înainte să seteze propria sa, nimic de curățat singur; ce contează
  este doar ca `tailscale serve`, niciodată o conexiune directă, să poată ajunge la
  miner — leagă-l de `127.0.0.1` și lasă doar Serve să facă de intermediar.

Indiferent ce proxy alegi, testează-l o dată înainte să ai încredere în el: cu SSO
deconectat, fă un `curl` direct la adresa miner-ului însuși (ocolind proxy-ul, de pe
mașina sau containerul pe care rulează) cu antetul setat manual, precum
`curl -H "Remote-User: mallory" http://127.0.0.1:8080/api/snapshot`; trebuie să
răspundă cu `401`, niciodată cu instantaneul.

Exemple Compose testate, gata de copiat și lipit, pentru cinci configurații comune:

| Proxy | Exemplu | Ce arată |
|---|---|---|
| Traefik + Authelia | [`docs/reverse-proxy/traefik-authelia/`](docs/reverse-proxy/traefik-authelia/) | O stivă completă de single sign-on: Authelia reală, backend pe fișier, forward-auth prin Traefik. |
| Caddy | [`docs/reverse-proxy/caddy/`](docs/reverse-proxy/caddy/) | `forward_auth` + `copy_headers`, cea mai scurtă configurație dintre cele cinci. |

### <a name="systemd"></a>Fără Docker (systemd)

Pe un server Linux fără Docker, versiunea publicată conține și serverul ca un singur
fișier, cu panoul inclus: `twitch-miner-server_<versiune>_linux_x64` sau
`twitch-miner-server_<versiune>_linux_arm64`. Este programul pe care îl rulează imaginea
Docker, compilat static: nu mai e nevoie să instalezi altceva, cu excepția
certificatelor CA ale sistemului pe care le citește pentru HTTPS (imaginea Docker le
copiază din același motiv). Folosește aceleași variabile.

```bash
# ARM64: twitch-miner-server_<versiune>_linux_arm64
sudo install -m 755 twitch-miner-server_<versiune>_linux_x64 /usr/local/bin/twitch-miner
sudo install -m 600 /dev/null /etc/twitch-miner.env
```

Scrie propria parolă, de cel puțin 12 caractere, în `/etc/twitch-miner.env`, pe care doar
root îl poate citi:

```ini
MINER_PASSWORD=change-me
```

Apoi serviciul, în `/etc/systemd/system/twitch-miner.service`:

```ini
[Unit]
Description=Twitch Miner
Wants=network-online.target
After=network-online.target

[Service]
ExecStart=/usr/local/bin/twitch-miner
EnvironmentFile=/etc/twitch-miner.env
Environment=DATA_DIR=/var/lib/twitch-miner
DynamicUser=yes
StateDirectory=twitch-miner
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now twitch-miner
```

systemd creează `/var/lib/twitch-miner` pentru date și rulează serverul sub propriul
utilizator, niciodată ca root. Deschide `http://<adresa serverului>:8080`; logurile sunt
în `journalctl -u twitch-miner`.

Acest fișier nu se actualizează singur. Când panoul arată o versiune nouă, descarcă noul
fișier din versiunea publicată, apoi înlocuiește-l pe cel vechi și repornește:

```bash
# ARM64: twitch-miner-server_<versiune>_linux_arm64
sudo install -m 755 twitch-miner-server_<versiune>_linux_x64 /usr/local/bin/twitch-miner
sudo systemctl restart twitch-miner
```

## <a name="how-it-works"></a>Cum funcționează

La fiecare 20 de secunde, fiecare cont își alege cele două canale: cel mai bun canal live
pentru prima campanie din coada sa, apoi streamerii din lista sa de puncte. O campanie fără
canal live este sărită în favoarea următoarei care are unul („Niciun canal live” în coada
ei); canalele live sunt reverificate la fiecare 90 de secunde, iar contul revine la ea
imediat ce unul dintre streamerii săi intră live.

Twitch creditează simultan, per cont, **o singură campanie Drops** și **două canale pentru
puncte**. Din octombrie 2026, un drop poate fi revendicat doar dacă este conectat contul de
editor. Campaniile neconectate progresează oricum, iar panoul afișează linkul de conectare.

Dacă progresul Twitch pe campania de top nu avansează după 30 de minute de vizionare
reală, înseamnă că nu o creditează: contul o pune deoparte, campania următoare în clasament
preia locul, iar o nouă încercare are loc automat 6 ore mai târziu — mai devreme, dacă
progresul reapare înainte, deși campania reîncercată poate încă aștepta după cea care este
minată în prezent. Orice progres resetează așteptarea, iar asta se aplică fiecărui tip de
campanie (Drops, insigne, misiuni). Dacă Twitch creditează în schimb o altă campanie din aceeași categorie, iar aceasta se încheie sau este revendicată, amânarea este ridicată imediat, în loc să aștepte cele 6 ore complete. Repornirea aplicației sau a serverului uită toate
campaniile puse deoparte: o campanie blocată primește pur și simplu încă 30 de minute noi.

Lista campaniilor vine de la proiectul [Drops Alerts](https://dropsalerts.com)
(reîmprospătată la fiecare 5 minute), pentru că Twitch o ascunde de clientul TV.

## <a name="faq"></a>Întrebări frecvente

### Riscuri și Twitch

**Îmi poate fi banat contul?**\
Nimeni nu poate garanta că nu. Acest proiect nu este afiliat cu Twitch, iar automatizarea
unui cont poate încălca termenii săi sau regulile unei campanii. Minerul urmărește cel mult
două canale per cont, limita Twitch, fără să descarce vreun videoclip. Decizia îți
aparține.

**Chiar se urmărește videoclipul?**\
Nu, nu se descarcă niciun videoclip. Pentru Drops, la fiecare 15 secunde minerul citește
playlistul streamului la cea mai mică calitate și cere doar antetul fiecărui segment nou.
Pentru puncte, trimite în fiecare minut semnalul Twitch de „minut vizionat”. Fiecare canal
urmărit arată câte segmente au fost cerute.

**De ce cel mult două canale?**\
Aceasta e limita Twitch: creditează doar două canale urmărite în același timp per cont și
o singură campanie Drops odată. În modul **Drops și puncte**, un canal servește campania,
iar celălalt streamerii tăi. Setarea „Un canal”, din **Setări cont**, e mai discretă.

### Drops

**O campanie nu este minată sau un drop nu avansează.**\
Deschide pagina **Drops** a contului. În „Ordinea de minare”, fiecare campanie în
așteptare spune de ce: „Niciun canal live” sau „În așteptare (o campanie pe rând)”.
„Twitch nu o contorizează — reîncercare …” înseamnă că 30 de minute de vizionare reală nu
au adus niciun progres din partea Twitch: campania este pusă deoparte și reîncercată
automat după timpul afișat, sau mai devreme, dacă progresul reapare înainte. O campanie
care nu apare în acea listă a fost lăsată deoparte: de „Ce să se mineze, în ordine”, de
setarea „Ce campanii”, de o regulă din fila **Excluderi**, pentru că nu se poate termina
la timp sau pentru că toate recompensele rămase cer un abonament. O recompensă care cere
un abonament așteaptă să te abonezi sau să oferi un abonament cadou în timpul campaniei,
pe un canal din categorie (un abonament deja activ, un abonament Prime sau o reînnoire nu
contează), o insignă de urmărit în fiecare zi așteaptă ziua următoare, nimic nu este minat
înainte de începutul campaniei, iar un drop care urmează după altul așteaptă ca primul să
se termine. În modul **Doar puncte**, minerul nu alege nicio campanie. „Minează cu
prioritate”, în fișa unei campanii, o pune pe primul loc; o campanie ignorată poate reveni
cu „Minează din nou”, din fila **Excluderi**. Fila **Campanii** arată aceleași motive în
grupul **Blocate**.

**Trebuie să conectez contul de editor?**\
Pentru revendicare, da: din octombrie 2026, Twitch permite revendicarea unui drop doar
dacă contul de editor este conectat. Implicit, o campanie neconectată progresează oricum, iar
revendicarea așteaptă conectarea. Insigna „Neconectat” semnalează asta, iar „Conectează
contul de editor”, din fișa campaniei, deschide pagina de conectare. Ca să minezi doar
categoriile conectate, alege „Doar categoriile al căror cont de editor este conectat”.

### Instalare și date

**Aplicație desktop sau Docker?**\
Aplicația desktop minează cât timp PC-ul tău e pornit, cu pictograma din bara de sistem, o
parolă opțională și actualizări dintr-un clic. Docker minează zi și noapte pe o mașină
mereu pornită (VPS, NAS, Raspberry Pi); îl deschizi într-un browser, protejat de
`MINER_PASSWORD`. Interfața este aceeași.

**Unde sunt datele mele?**\
În dosarul de date: `~/.local/share/twitch-miner` pe Linux,
`%APPDATA%\twitch-miner` pe Windows,
`~/Library/Application Support/twitch-miner` pe macOS și volumul `/data` cu
Docker. Pe desktop, **Setări › Desktop** îl deschide dintr-un clic. Conține `miner.db`
(conturi, setări, jurnal), `master.key` (cheia sesiunilor, când nu e setată nicio parolă a
aplicației) și logurile.

**Cum actualizez?**\
Aplicația desktop verifică la pornire dacă există o versiune nouă, apoi la fiecare oră
(poți schimba asta în **Setări › Despre**), și te poate anunța când găsește una. Dă clic
pe insigna „Actualizare”, apoi pe „Instalează și repornește”. Cu Docker, panoul te
anunță: rulează `docker compose pull`, apoi `docker compose up -d`. Fără Docker, panoul
te anunță la fel: vezi [Fără Docker](#systemd) ca să înlocuiești fișierul și să repornești
serviciul. Aplicația arată schimbările fiecărei versiuni apărute după a ta, de la cea mai
nouă; notele fiecărei versiuni sunt și în pagina ei de pe GitHub.

**Am uitat parola aplicației.**\
Nu poate fi recuperată: ea criptează sesiunile tale Twitch. Închide aplicația, șterge
dosarul de date, apoi adaugă din nou conturile; setările lor trebuie refăcute. Cu Docker,
parola panoului se schimbă în `MINER_PASSWORD`, urmată de `docker compose up -d`.

### Puncte și predicții

**Câte puncte pe oră?**\
Depinde de Twitch și de fiecare canal. Minerul câștigă ce îi dă Twitch unui spectator:
punctele pentru timpul de vizionare, cuferele bonus (cam unul la fiecare 15 minute) și
bonusul pentru seria de vizionare. Un abonament înmulțește punctele, de la ×1,2 la ×2, în
funcție de nivel, iar cu „Canalele cu abonament mai întâi”, activată implicit, aceste
canale trec înaintea restului listei tale. Pagina Acasă arată punctele câștigate, iar
Jurnalul, fiecare câștig.

**Sunt riscante pariurile?**\
Da, se pot pierde puncte. Predicțiile sunt dezactivate implicit, streamer cu streamer. Tu
alegi strategia, momentul pariului, miza (5 % din sold implicit, cel mult 50.000 de
puncte), un sold minim și, dacă vrei, o condiție, de exemplu o cotă de cel puțin 1,5.
Păstrează miza mică.
Un pariu sub 10 puncte nu este plasat niciodată.

**Un streamer nu este urmărit.**\
Sunt urmăriți doar streamerii activați și live, și doar pe un canal liber: în modul
**Drops și puncte**, unul dintre cele două servește campania curentă; în modul
**Doar Drops**, nu este urmărit niciun streamer; un cont pus pe pauză nu urmărește nimic.
Locurile se ocupă în această ordine, afișată ca insignă pe fiecare canal urmărit: „Serie
în pericol”, „Bonus de serie”, „Abonat”, apoi „Ordinea listei”. Mută streamerul mai sus în
listă sau dezactivează „Seriile de vizionare mai întâi” și „Canalele cu abonament mai
întâi”.

## <a name="security"></a>Securitate

- Tokenurile sunt sigilate cu AES-256-GCM. Cheia este fie un `master.key` aleator lângă
  baza de date (implicit, nimic de făcut), fie derivată din parola aplicației cu Argon2id.
- Dosarul de date și cel de loguri sunt private (`0700`): doar utilizatorul care rulează
  minerul le poate deschide.
- Panoul HTTP verifică parola în timp constant și folosește cookie-uri HttpOnly,
  SameSite=Strict (`Secure`, cu prefixul `__Host-`, în spatele HTTPS). Serverul păstrează
  doar un hash SHA-256 al fiecărei sesiuni. Încheie o sesiune după 30 de zile sau la
  deconectare. Verifică sesiunea înainte de a citi orice corp de cerere și limitează
  corpurile la 256 KiB.
- După 5 parole greșite la rând de la aceeași adresă IP (formularul de autentificare sau
  bearer), acea adresă așteaptă 30 de secunde. Serverul răspunde `429` cu `Retry-After`,
  fără să se uite la parolă. În plus, fiecare parolă greșită primește răspuns abia după
  o jumătate de secundă.
  Peste 30 de parole greșite într-un minut de la aceeași adresă de conexiune, inclusiv un
  proxy comun, acea adresă primește o singură încercare la fiecare 2 secunde: ghicitul
  încetinește și nimeni nu rămâne blocat.
- În afara rețelei tale, pune panoul în spatele unui reverse proxy HTTPS cu
  `MINER_PUBLIC_URL` (vezi [Docker](#docker)).
- Minerul comunică doar cu `twitch.tv`, `ttvnw.net`, `jtvnw.net`, `twitchcdn.net`,
  `dropsalerts.com` și cu destinațiile de notificare pe care le configurezi.
  Aplicația (desktop și Docker) verifică versiunile noi și notele lor pe `github.com` și
  `api.github.com`, iar aplicația
  desktop le descarcă din versiunile proiectului pe GitHub. Sunt semnate: se instalează
  doar versiunea afișată.

## <a name="build"></a>Compilare din sursă

**Cerințe:** Rust, Node.js și
[cerințele preliminare Tauri](https://v2.tauri.app/start/prerequisites/) pentru sistemul
tău.

```bash
npm ci
npm run build          # panoul
cargo build --release -p miner-server   # serverul: target/release/twitch-miner
npm run bundle:linux   # pachetele desktop (necesită dependențele Tauri pentru Linux)
```

Verificări ale codului:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
npm run verify         # prettier, oxlint (cu analiză de tipuri), svelte-check și verificarea i18n inlang
```

Tipurile TypeScript ale interfeței sunt generate din tipurile Rust cu
[ts-rs](https://github.com/Aleph-Alpha/ts-rs) în `ui/src/lib/bindings`. După o modificare
a unui tip pe care îl vede interfața, rulează `npm run bindings`.
