<h1 align="center">Twitch Miner</h1>

<p align="center">
  <strong>Mina i Drops, i badge e i punti canale di Twitch su quanti account vuoi, senza browser e senza schede di Twitch aperte.</strong>
</p>

<p align="center">
  Un'app desktop per Linux, Windows e macOS, oppure un'immagine Docker con la stessa dashboard web, da eseguire su un server domestico o su un Raspberry Pi. Ogni account usa circa 3 MB di memoria e quasi niente CPU.
</p>

Su Linux puoi anche installare da un terminale. Su ARM64, sostituisci `x64` con `arm64`
nei comandi.

Debian, Ubuntu, Raspberry Pi OS:

```bash
curl -LO https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.deb
sudo apt install ./twitch-miner_linux_x64.deb
```

Fedora, openSUSE:

```bash
curl -LO https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.rpm
sudo dnf install ./twitch-miner_linux_x64.rpm
# openSUSE: sudo zypper install ./twitch-miner_linux_x64.rpm
```

AppImage, su qualsiasi distribuzione:

```bash
curl -LO https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.AppImage
chmod +x twitch-miner_linux_x64.AppImage
./twitch-miner_linux_x64.AppImage
```

Gli stessi comandi aggiornano un'installazione esistente: i nomi dei file non cambiano.

La build per macOS non è notarizzata. La prima volta, apri l'app: macOS la blocca. Poi vai
in **Impostazioni di sistema › Privacy e sicurezza** e fai clic su **Apri comunque**.

Gli aggiornamenti sono firmati. L'app controlla se c'è una nuova versione all'avvio, poi
ogni ora (puoi cambiare la frequenza in **Impostazioni › Informazioni**). Non ne installa
mai una da sola: la installi tu con un clic, dal messaggio che compare o da
**Impostazioni › Informazioni**.

I dati si trovano nella cartella dei dati dell'utente:

- Linux: `~/.local/share/twitch-miner`
- Windows: `%APPDATA%\twitch-miner`
- macOS: `~/Library/Application Support/twitch-miner`

## <a name="features"></a>Funzionalità

### Account e streamer

- **Tutti gli account che vuoi in un'unica app.** Ogni account mina per conto suo, nella sua modalità:
  **Drops e punti** (un canale per la campagna migliore, l'altro per i tuoi streamer),
  **Solo Drops** o **Solo punti**.

  <img src="../media/it/accounts-mining.avif" alt="Più account che minano contemporaneamente, nella pagina Home">

- **Una procedura guidata per ogni nuovo account.** Dopo l'accesso, parti dalle
  impostazioni predefinite o da quelle di un altro account. Scegli la modalità, le
  campagne e gli streamer, poi «Inizia il mining» o «Salva e avvia più tardi».

  <img src="../media/it/account-setup.avif" alt="La procedura guidata di configurazione di un nuovo account, passo dopo passo">

- **Una modifica applicata ad altri account con un clic.** Dopo aver cambiato qualcosa su
  un account, il messaggio di conferma propone «Applica ad altri account». La modifica
  viene ripetuta sugli account che spunti, che mantengono il resto delle loro impostazioni.

  <img src="../media/it/apply-to-accounts.avif" alt="Una modifica ripetuta su altri account con «Applica ad altri account»">

- **Aggiungere uno streamer.** Parte subito con le opzioni predefinite: quelle dell'app o
  quelle che hai scelto per questo account. Regolale al momento, se serve: forzieri bonus,
  raid, momenti, serie di visione, chat, previsioni.

  <img src="../media/it/streamer-add.avif" alt="Uno streamer aggiunto con la ricerca di Twitch, poi le sue opzioni">

- **Modificare uno streamer.** «Modifica» apre le sue opzioni: forzieri bonus, raid,
  momenti, serie di visione, chat, previsioni… Un interruttore lo attiva o lo disattiva
  senza toglierlo dalla lista.

  <img src="../media/it/streamer-edit.avif" alt="Le opzioni di uno streamer, aperte dalla sua riga">

- **Modificare più streamer insieme.** Spuntali, poi «Modifica i N streamer selezionati».
  Si applicano solo le opzioni che cambi. Un'opzione che differisce tra loro appare come
  «Misto», e il suo interruttore diventa due pulsanti, «Sì» e «No». L'app propone poi di
  farne le opzioni predefinite per i nuovi streamer.

  <img src="../media/it/streamers-group-edit.avif" alt="Modifica di più streamer, con opzioni «Misto»">

- **Importare streamer.** Incolla una lista (fino a 500 nomi), oppure riprendi quella di un
  altro account o i canali che l'account segue. La lista viene verificata per aggiungere
  solo canali che esistono.
  Gli aggiornamenti in diretta coprono 46 streamer per account: i successivi della lista
  non ricevono raid, momenti né previsioni.

  <img src="../media/it/streamers-import.avif" alt="Importazione di streamer: una lista incollata, un altro account, i canali seguiti">

- **Spam Points.** Riscatta più volte di fila un premio personalizzato di un canale.
  Scegli un canale dalla tua lista Punti, o qualsiasi canale trovato con la ricerca di
  Twitch: i suoi premi compaiono con il saldo dell'account, letto in tempo reale. Imposta
  la quantità (fino a 25, nei limiti del saldo), poi «Riscatta». Il risultato compare alla
  fine della raffica, e ogni raffica ha la sua riga nel Registro.

  <img src="../media/it/spam-points.avif" alt="Spam Points: un canale scelto, 10 × un premio con messaggio riscattato, i riscatti arrivano nella chat Twitch del canale, poi la riga del Registro">

### Drops

- **Tutte le campagne Drops in corso.** Ogni campagna ha i suoi dettagli: ricompense,
  collegamento dell'account editore, «Mina per prima». L'elenco arriva dal progetto
  [Drops Alerts](https://dropsalerts.com) e si aggiorna ogni 5 minuti.

  <img src="../media/it/drops-catalogue.avif" alt="Il Catalogo in vista calendario, la ricerca e i dettagli di una campagna">

- **Il tuo ordine di mining.** Trascina le campagne nell'ordine che preferisci. Le nuove
  trovano posto da sole: prima le tue categorie prioritarie, poi quelle che finiscono prima o
  a cui mancano meno minuti. Escludi categorie, parole, una campagna o una singola
  ricompensa, e salta le campagne che non possono finire in tempo. «Mina per prima», nei
  dettagli di una campagna, la porta in cima.

  <img src="../media/it/drops-order.avif" alt="L'ordine di mining, le categorie prioritarie e le esclusioni">

- **Inventario e «Riscatta tutto».** La pagina Inventario divide le ricompense in
  «Da riscattare», «In corso» e «Riscattate». Riscattale una alla volta, tutte insieme,
  oppure attiva «Riscatta i drop automaticamente».
  Dopo «Collega l'account editore», l'account viene riletto appena torni nell'app, così il
  collegamento compare subito.

  <img src="../media/it/drops-inventory.avif" alt="L'inventario e il pulsante «Riscatta tutto»">

- **«Prima i miei streamer per i Drops e i badge».** Per la campagna in corso, uno streamer della
  tua lista la cui live vale per quella campagna passa davanti agli altri canali. Lo
  stesso canale fa avanzare il drop e ti fa guadagnare i suoi punti canale. Attivo per
  impostazione predefinita.

  <img src="../media/it/drops-streamers-first.avif" alt="Uno streamer della lista, guardato per i Drops e per i suoi punti">

- **Priorità delle ricompense.** Quando due campagne hanno la stessa posizione, il miner
  sceglie prima quella con ricompense del tipo che preferisci (badge, emote, oggetto di
  gioco). Non scavalca mai il tuo ordine di mining.

- **Badge (beta).** La pagina Badge elenca tutti i badge globali della chat di Twitch e
  come ottenerli. Ogni account ha la sua pagina Badge: i badge in corso con i loro
  progressi, quelli ancora da ottenere e quelli che possiede. Il miner punta ai badge
  delle campagne Drops e delle missioni Twitch, e salta quelli che l'account possiede già.
  Un badge da guardare ogni giorno viene minato di nuovo ogni giorno fino all'ultimo («20
  min al giorno, 3 giorni»), e conta un canale di una qualsiasi delle categorie della
  campagna. Un forziere dà «1 badge a caso su N». Un badge che richiede un abbonamento
  viene minato una volta che ti sei abbonato o hai regalato un abbonamento durante la
  campagna, su un canale della categoria, e Twitch lo conta. Un abbonamento già attivo, un
  abbonamento Prime o un rinnovo non contano. Niente viene minato prima dell'inizio della
  sua campagna. In «Cosa minare, in ordine», trascina le categorie prioritarie, i badge e
  le altre campagne Drops nell'ordine che vuoi, oppure disattivane uno. Una missione
  Twitch viene minata solo su un canale in cui Twitch la offre nel suo pannello Drops.
  Un'evoluzione (Pichu → Pikachu) viene minata appena l'account possiede il badge da cui
  evolve: il miner equipaggia da solo quel badge subito prima e non rimette quello
  precedente; «Mina le evoluzioni dei badge», nelle impostazioni dei badge dell'account,
  lo disattiva. Un clic su un badge apre i suoi dettagli: il requisito completo, tutte le
  categorie e i canali, la collezione, l'evoluzione e i progressi di ogni account. Questa
  funzione è in beta.

  <img src="../media/it/badges.avif" alt="La pagina Badge, i badge di un account, poi «Cosa minare, in ordine» con Badge trascinato in cima">

### Monitoraggio

- **Un registro di tutto, e ogni richiesta.** Il Registro conserva ogni evento: drop, punti
  guadagnati e spesi, forzieri, scommesse, raid, live che iniziano… Filtralo per account,
  per scheda (Drops, Badge, Punti, Altro) e per tipo. **Log tecnici › Richieste** elenca ogni
  richiesta inviata a Twitch e ad altri servizi, con il suo esito e la sua durata. Log e
  richieste non contengono alcun token né segreto: «Copia per una segnalazione di bug» li
  copia, pronti da incollare in una segnalazione di bug su
  [GitHub](https://github.com/SunkwiBOT/twitch-miner/issues) o
  [Discord](https://discord.gg/support-bots-891685895781113886).

  <img src="../media/it/journal-requests.avif" alt="Il Registro filtrato, poi Log tecnici › Richieste">

- **Una pagina Statistiche.** Punti guadagnati, drop riscattati, tempo di visione e
  previsioni vinte su 7, 30 o 90 giorni, con lo streamer o la categoria in testa dietro
  ogni numero. Una curva dei punti per streamer mostra il saldo nel tempo, con indicatori
  per serie, raid, momenti e previsioni e un suggerimento su ciascuno.

  <img src="../media/it/stats.avif" alt="I riquadri della pagina Statistiche su 30 giorni, poi la curva dei punti di uno streamer con un indicatore">

- **Pausa e finestra silenziosa.** Un solo pulsante di pausa, per un account o per tutti:
  pausa finché non riprendi, oppure per 30 minuti, 1 ora, 4 ore, fino a domani alle 09:00,
  o una data e un'ora personalizzate; durante la pausa lo stesso pulsante dice «Riprendi».
  Un badge mostra l'ora in cui finisce una pausa a tempo, e ogni account nella barra
  laterale mostra il suo stato: attivo, in pausa o con un problema da controllare. Una
  finestra silenziosa giornaliera ferma il mining di tutti gli account ogni giorno tra due
  orari, nel fuso orario scelto, e lo riprende quando termina, con il suo badge nella
  barra in alto.
- **Esportazione CSV e conteggi per categoria.** Il Registro esporta i drop riscattati
  come file CSV (data, account, categoria, campagna, drop, minuti), filtrati per account,
  e una finestra di dialogo elenca quanti drop sono stati riscattati in ciascuna
  categoria. L'app desktop salva il file con una finestra di salvataggio; la dashboard web
  lo scarica.

### Sul desktop o su un server

- **La stessa interfaccia ovunque.** L'app desktop (Linux, Windows, macOS) e l'immagine
  Docker mostrano la stessa dashboard. Docker gira su un VPS, un NAS o un Raspberry Pi,
  senza schermo né browser su quella macchina: la dashboard si apre in qualsiasi browser.
  Sul telefono la dashboard si adatta allo schermo e, in HTTPS, si installa come un'app.
- **Leggero.** Circa 3 MB di memoria per account, quasi niente CPU e un'immagine Docker
  di circa 12 MB.

### Sicurezza e aggiornamenti

- **Le tue sessioni, protette.** Nessuna password di Twitch: accedi su
  `twitch.tv/activate`, dal tuo browser. Le sessioni sono cifrate su disco e puoi
  revocarle nelle tue [impostazioni di Twitch](https://www.twitch.tv/settings/connections).
  Sul desktop, una password dell'app facoltativa la blocca: non si mina nulla finché non
  viene inserita. Con Docker, la dashboard ha la sua password, si blocca da sola dopo
  qualche minuto di inattività e passa in HTTPS dietro un proxy. Cinque password errate di
  fila bloccano l'indirizzo IP per 30 secondi.

  <img src="../media/it/security-lock.avif" alt="Il lucchetto: l'app bloccata, poi sbloccata con la sua password">

- **Aggiornamenti firmati, mai automatici.** Nella barra in alto compare un badge
  «Aggiornamento» con il numero di versione, e anche una notifica desktop avvisa,
  attiva per impostazione predefinita (un interruttore in
  **Impostazioni › Notifiche** la disattiva; nel browser, fai clic su «Consenti»
  quando lo chiede). «Installa e riavvia» chiede prima una conferma, poi l'app installa
  la versione e si riavvia. Con una password dell'app, si riavvia bloccata: reinseriscila
  per riprendere il mining. Viene installata solo una versione firmata dal progetto. Anche
  la dashboard Docker e il binario systemd avvisano, con i comandi da eseguire.

  <img src="../media/it/updates.avif" alt="Il badge «Aggiornamento», la conferma, poi l'installazione">

### E inoltre

- Come altri miner: forzieri bonus, raid, momenti, obiettivi della community, previsioni
  (strategie, momento della scommessa, condizioni), priorità alle serie di visione e ai
  canali abbonati, presenza in chat (disattivabile), opzioni predefinite per i nuovi
  streamer, notifiche Discord, Telegram e webhook con immagini e un pulsante «Prova» per
  ciascuna (sul server, la loro lingua si sceglie in **Impostazioni › Notifiche**), proxy
  globale o per account.
- 29 lingue, temi scuro e chiaro, notifiche desktop, icona nell'area di notifica, avvio con
  il sistema.

  <img src="../media/it/basics.avif" alt="Lingue, tema chiaro e scuro, una notifica desktop e l'icona nell'area di notifica">

- **Aggiungere account incollando un elenco di token.** Hai già effettuato l'accesso altrove? Incolla un elenco di token di accesso, uno per riga (massimo 50); ciascuno viene verificato in tempo reale, con un contatore «Verificati: n/N» e un nuovo tentativo per ogni riga non riuscita, poi un unico passaggio di impostazioni si applica a tutto il lotto. L'importazione avviene in background, con avanzamento in tempo reale per ogni account, può essere annullata a metà, e un nuovo tentativo successivo reinvia solo gli account non riusciti. Rimuovendo un account importato in questo modo, viene proposto anche di revocarne il token su Twitch.

> Questo progetto non è affiliato a Twitch. Automatizzare un account può violare i termini
> di Twitch o le regole di una campagna.

## <a name="docker"></a>Docker

Il server mostra la stessa dashboard in un browser. L'immagine è
`ghcr.io/sunkwibot/twitch-miner`, per `amd64` e `arm64`. Quando esce una
nuova versione, la dashboard lo segnala: `docker compose pull`, poi
`docker compose up -d`.

```yaml
services:
  miner:
    image: ghcr.io/sunkwibot/twitch-miner:latest
    pull_policy: always   # scarica l'immagine più recente a ogni avvio
    restart: unless-stopped
    ports: ["8080:8080"]   # dietro un reverse proxy HTTPS: da togliere, o "127.0.0.1:8080:8080"
    environment:
      MINER_PASSWORD: "change-me"   # obbligatoria, 12 caratteri o più
      # MINER_PUBLIC_URL: "https://miner.example.com"   # solo dietro un reverse proxy HTTPS
    volumes:
      - miner-data:/data

volumes:
  miner-data:
```

```bash
docker compose up -d
```

Apri <http://localhost:8080> (o l'indirizzo della macchina sulla tua rete) e inserisci la
password.

### Variabili

| Variabile | Predefinito | Scopo |
|---|---|---|
| `MINER_PASSWORD` | nessuno | Password della dashboard, obbligatoria: senza, il server si rifiuta di avviarsi. Di 12 caratteri o più (una più corta mostra un avviso all'avvio). Il valore di esempio `change-me` viene rifiutato. |
| `MINER_PASSWORD_FILE` | nessuno | Legge `MINER_PASSWORD` da un file, per esempio un secret Docker. L'una o l'altra, non entrambe. |
| `MINER_PUBLIC_URL` | nessuno | Solo dietro un reverse proxy HTTPS (Caddy, nginx, Traefik, Cloudflare Tunnel…): l'indirizzo `https://` della dashboard, senza percorso, come `https://miner.example.com`. Il proxy deve inoltrare `X-Forwarded-Proto`, `X-Forwarded-For` e i websocket, cosa che i proxy più diffusi fanno già di default, e la porta del container non deve essere raggiungibile direttamente. La dashboard rifiuta quindi tutto ciò che non passa dal proxy in HTTPS, e blocca un indirizzo per 30 secondi dopo 5 password errate. Il proxy deve girare sulla stessa macchina o sulla sua rete locale: una connessione da un indirizzo pubblico viene rifiutata. |
| `MINER_TRUSTED_HOPS` | `1` | Solo con `MINER_PUBLIC_URL`: quanti proxy aggiungono una voce a `X-Forwarded-For`, da 1 a 10. `2` con due proxy uno dietro l'altro, come Cloudflare davanti a Traefik. |
| `MINER_PROXY_NETWORKS` | nessuno | Solo con `MINER_PUBLIC_URL`: le reti da cui si collega il proxy, separate da virgole, spazi o a capo: un singolo indirizzo o una rete come `192.168.1.0/24` o `2001:db8:1::/64`. Una volta impostata, il proxy è accettato solo dall'indirizzo di loopback e da queste reti, non più da tutta la rete locale privata. Un valore vuoto, un `/0` o una rete con bit host impostati fermano l'avvio solo se è impostato anche `MINER_AUTH_HEADER`; senza di esso, sono accettati con un avviso. |
| `MINER_AUTH_HEADER` | nessuno | Forward auth / SSO: il nome di un header che il proxy imposta sull'utente che ha effettuato l'accesso: `Remote-User` per Authelia, `X-authentik-username` per Authentik, `X-Auth-Request-User` per oauth2-proxy (con `--set-xauthrequest`). Una richiesta ammessa tramite il proxy — da un indirizzo presente in `MINER_PROXY_NETWORKS`, con un `Host` che corrisponde a `MINER_PUBLIC_URL` — con una riga non vuota in quell'header accede senza `MINER_PASSWORD`. Richiede `MINER_PUBLIC_URL` e una `MINER_PROXY_NETWORKS` esplicita; il solo loopback non basta mai per questo. Rifiuta un header che il proxy, un browser o un client scrive già (`X-Forwarded-*`, `Host`, `Cookie`, `Authorization`, `X-Real-IP`, `Forwarded`, `Via`, `User-Agent`, `Accept*`, `Sec-Fetch-*`, `Cache-Control`, `CF-Connecting-IP`, `Priority`, `Connection`, `Origin`, `Referer`, `X-Request-Id`, `Content-Type`…). |
| `MINER_AUTH_USERS` | nessuno | Solo con `MINER_AUTH_HEADER`: i valori dell'header autorizzati ad accedere, separati da virgole, spazi o a capo, come `MINER_PROXY_NETWORKS`. Il confronto distingue maiuscole e minuscole. Un valore impostato ma che non nomina nulla è rifiutato, come una `MINER_PROXY_NETWORKS` vuota con l'header impostato. Senza di esso, qualsiasi valore impostato dal proxy accede — ogni utente SSO che accede è un amministratore — e il server avvisa di questo all'avvio; con esso, il server registra il conteggio analizzato all'avvio. |
| `MINER_VAULT_PASSPHRASE` | nessuno | Solo per una cartella dei dati copiata dall'app desktop con una password dell'app: la sblocca all'avvio. Un server creato da zero non ne ha mai bisogno. |
| `MINER_VAULT_PASSPHRASE_FILE` | nessuno | Legge `MINER_VAULT_PASSPHRASE` da un file. L'una o l'altra, non entrambe. |
| `DATA_DIR` | `/data` nell'immagine, altrimenti `data` nella directory di lavoro | Database, file della chiave e log. |
| `LOG_DIR` | `$DATA_DIR/logs` | File di log: uno al giorno, vengono conservati gli ultimi 14. |
| `HOST` / `PORT` | `0.0.0.0` / `8080` | Indirizzo di ascolto: un indirizzo IP e una porta da 1 a 65535. |
| `RUST_LOG` | `info,hyper=warn,reqwest=warn` | Livello di log. |

Il server legge e controlla le variabili una sola volta, all'avvio. Un valore non valido
arresta il server con un messaggio, invece di ripiegare in silenzio su un valore di
riserva.

Dietro un reverse proxy, imposta `MINER_PUBLIC_URL`: senza, la prima richiesta che arriva
da un proxy scrive un avviso nei log, perché i tentativi di accesso vengono allora contati
sull'indirizzo del proxy, e le password sbagliate di un visitatore bloccherebbero tutti.
La connessione in tempo reale invia un ping ogni 30 secondi, così un proxy non la chiude
quando non succede nulla. Quando Twitch o la rete non rispondono, il server risponde
`424`, mai `502` o `504`: dietro Cloudflare, vedi il vero errore invece della pagina di
Cloudflare.

#### Accedere da un proxy fidato (forward auth / SSO)

_Disponibile a partire dalla v1.16.0._

Con un unico accesso davanti a più app self-hosted (Authelia, Authentik, oauth2-proxy…),
`MINER_AUTH_HEADER` salta la password propria della dashboard: basta l'accesso al proxy.
Imposta anche `MINER_AUTH_USERS` con i valori consentiti, altrimenti qualsiasi utente SSO
accede come amministratore. `MINER_PASSWORD` continua a funzionare per gli script che
accedono direttamente con `POST /api/auth`, mai da un browser: il router sotto invia
ogni altra richiesta attraverso `forwardAuth`, quindi un browser che visita la
dashboard ha sempre bisogno dell'SSO attivo. Un secondo router agisce solo su `POST` e
`DELETE` su `/api/auth` — l'accesso e l'uscita con password — e svuota l'header da
solo invece di rimuovere `forwardAuth`: allargare la sua regola oltre quel percorso
lascerebbe passare anche un header falsificato dal client.

Il proxy deve mantenere invariato l'`Host` originale della richiesta verso il miner,
altrimenti `MINER_PUBLIC_URL` non corrisponde mai e l'header viene ignorato in silenzio,
con un avviso nei log la prima volta: nginx ha bisogno di `proxy_set_header Host $host;`,
Apache ha bisogno di `ProxyPreserveHost On`. Traefik e Caddy lo mantengono invariato di
default, nulla da aggiungere per entrambi.

Nessuno di questi prodotti rimuove un header inviato dal client stesso: ogni percorso dal
proxy al miner ha bisogno di una propria regola che lo sovrascriva (il `forwardAuth` di
Traefik elimina solo gli header elencati in `authResponseHeaders`, e inoltra invariato
qualsiasi altro header del client). Esegui il proxy e il miner da soli sulla propria
rete, con un indirizzo statico per il proxy, e non pubblicare mai la porta del miner:
qualsiasi altra cosa che la raggiunga — un altro container, un processo dell'host —
potrebbe impostare l'header da sola.

Authelia dietro Traefik, entrambi da soli su `miner-net`, che inoltra l'utente che ha
effettuato l'accesso in `Remote-User`:

```yaml
networks:
  edge: {}          # qui comunicano Traefik e Authelia
  miner-net:        # solo Traefik e il miner sono su questa
    ipam:
      config:
        - subnet: 10.10.0.0/29

services:
  traefik:
    # la tua normale configurazione Traefik: entrypoint, altre reti, altre app
    networks:
      edge: {}
      miner-net:
        ipv4_address: 10.10.0.2

  authelia:
    # la tua normale configurazione Authelia
    networks:
      edge: {}
    labels:
      traefik.http.middlewares.authelia.forwardAuth.address: "http://authelia:9091/api/authz/forward-auth"
      traefik.http.middlewares.authelia.forwardAuth.trustForwardHeader: "true"
      traefik.http.middlewares.authelia.forwardAuth.authResponseHeaders: "Remote-User"
      # per il router degli script sotto: svuota Remote-User invece di saltare
      # l'autenticazione, così un header falsificato dal client non funziona neanche lì
      traefik.http.middlewares.blank-remote-user.headers.customrequestheaders.Remote-User: ""

  miner:
    image: ghcr.io/sunkwibot/twitch-miner:latest
    networks:
      miner-net:
        ipv4_address: 10.10.0.3   # statico anche qui: un indirizzo casuale potrebbe collidere
    # niente "ports": questa rete raggiunge solo Traefik, da 10.10.0.2
    environment:
      MINER_PASSWORD: "change-me"
      MINER_PUBLIC_URL: "https://miner.example.com"
      MINER_PROXY_NETWORKS: "10.10.0.2"
      MINER_AUTH_HEADER: "Remote-User"
      MINER_AUTH_USERS: "alice,bob"
    volumes:
      - miner-data:/data
    labels:
      traefik.http.routers.miner.rule: "Host(`miner.example.com`)"
      traefik.http.routers.miner.middlewares: "authelia@docker" # ripeti su ogni router verso il miner
      # per gli script, con MINER_PASSWORD: aggira Authelia, mai lo svuotamento dell'header
      traefik.http.routers.miner-api.rule: "Host(`miner.example.com`) && Path(`/api/auth`) && (Method(`POST`) || Method(`DELETE`))"
      traefik.http.routers.miner-api.middlewares: "blank-remote-user@docker"

volumes:
  miner-data:
```

#### Rafforzare un altro proxy

Nessuno di questi prodotti rimuove da solo una copia dell'header inviata dal client:
aggiungere la riga di rimozione qui sotto prima della direttiva che lo imposta dalla
risposta dello SSO, su ogni rotta verso il miner, inclusa quella degli script. Traefik,
Caddy, nginx, Apache e HAProxy sono stati verificati ciascuno su un'istanza reale che
termina il TLS, con un header falsificato, uno duplicato e una variante di
maiuscole/minuscole o trattino basso; Cloudflare Tunnel e Tailscale Serve provengono
dalla loro documentazione e dal codice sorgente, non testati in modo indipendente qui.

- **nginx**: `auth_request` si limita a validare, non tocca mai gli header da solo —
  una configurazione che lo chiama ma non imposta mai `Remote-User` inoltra la riga
  del client invariata (provato: un `Remote-User: admin` falsificato è arrivato al
  miner letteralmente senza le due righe seguenti). Aggiungere sempre
  `auth_request_set $auth_user $upstream_http_remote_user;` e poi
  `proxy_set_header Remote-User $auth_user;`, che lo sovrascrive — mai facoltativo.
  Anche `proxy_set_header Host $host;`, oppure `$http_host` se `MINER_PUBLIC_URL`
  indica una porta non standard (`$host` toglie la porta, e l'header non viene più
  mai fidato in silenzio). nginx scarta anche qualsiasi header il cui nome contenga
  un trattino basso, a meno che `underscores_in_headers on;` non sia attivo: per
  questo `MINER_AUTH_HEADER` rifiuta un nome simile.
- **Caddy**: `forward_auth` con `copy_headers Remote-User` già sovrascrive da solo una
  copia del client, provato, non serve altro. `request_header -Remote-User` subito
  prima è difesa in profondità extra innocua, non un requisito, a differenza di
  Traefik, dove un secondo router che salta del tutto `forwardAuth` ha davvero
  bisogno dell'azzeramento esplicito.
- **Apache**: `RequestHeader unset Remote-User` incondizionatamente, poi
  `RequestHeader set Remote-User "…" env=AUTH_OK` da ciò che convalida la sessione, e
  `ProxyPreserveHost On` per lo stesso requisito di `Host` visto sopra.
- **HAProxy**: `http-request del-header Remote-User` incondizionatamente, poi
  `http-request set-header Remote-User alice if <acl-sessione-valida>`. HAProxy non
  tocca neppure `X-Forwarded-For` da solo: aggiungere
  `http-request set-header X-Forwarded-For %[src]`, altrimenti un valore falsificato
  raggiunge il miner invariato.
- **Cloudflare Tunnel**: lasciare `httpHostHeader` non impostato (di default inoltra già
  l'`Host` pubblico richiesto dal client); è un tunnel, non un proxy che ripulisce gli
  header, quindi abbinarlo a uno dei proxy sopra per `MINER_AUTH_HEADER` invece di
  fidarsi di lui da solo.
- **Tailscale Serve**: `Tailscale-User-Login`. `tailscaled` elimina già ogni copia
  inviata dal client prima di aggiungere la propria, nulla da ripulire manualmente;
  conta solo che sia `tailscale serve`, mai una connessione diretta, a raggiungere il
  miner — associarlo a `127.0.0.1` e lasciare che solo Serve faccia da tramite.

Qualunque sia il proxy scelto, testatelo una volta prima di fidarvene: con lo SSO
disconnesso, fate un `curl` diretto all'indirizzo del miner stesso (bypassando il proxy,
dalla macchina o dal container su cui gira) con l'header impostato a mano, come
`curl -H "Remote-User: mallory" http://127.0.0.1:8080/api/snapshot`; deve rispondere
`401`, mai lo snapshot.

Esempi Compose testati e pronti da copiare e incollare per cinque configurazioni comuni:

| Proxy | Esempio | Cosa mostra |
|---|---|---|
| Traefik + Authelia | [`docs/reverse-proxy/traefik-authelia/`](docs/reverse-proxy/traefik-authelia/) | Uno stack completo di single sign-on: Authelia reale, backend su file, forward-auth tramite Traefik. |
| Caddy | [`docs/reverse-proxy/caddy/`](docs/reverse-proxy/caddy/) | `forward_auth` + `copy_headers`, la configurazione più breve delle cinque. |
| nginx | [`docs/reverse-proxy/nginx/`](docs/reverse-proxy/nginx/) | `auth_request`, con la riga di sovrascrittura facile da dimenticare per errore — e cosa succede se succede. |

### <a name="systemd"></a>Senza Docker (systemd)

Su un server Linux senza Docker, la release include anche il server come file unico, con
la dashboard al suo interno: `twitch-miner-server_<versione>_linux_x64` o
`twitch-miner-server_<versione>_linux_arm64`. È lo stesso programma eseguito
dall'immagine Docker, collegato staticamente: non c'è nient'altro da installare, a parte
i certificati CA di sistema che legge per l'HTTPS (anche l'immagine Docker li copia per lo
stesso motivo). Prende le stesse variabili.

```bash
# ARM64: twitch-miner-server_<versione>_linux_arm64
sudo install -m 755 twitch-miner-server_<versione>_linux_x64 /usr/local/bin/twitch-miner
sudo install -m 600 /dev/null /etc/twitch-miner.env
```

Scrivi la tua password, di 12 caratteri o più, in `/etc/twitch-miner.env`, leggibile solo
da root:

```ini
MINER_PASSWORD=change-me
```

Poi il servizio, in `/etc/systemd/system/twitch-miner.service`:

```ini
[Unit]
Description=Twitch Miner
Wants=network-online.target
After=network-online.target

[Service]
ExecStart=/usr/local/bin/twitch-miner
EnvironmentFile=/etc/twitch-miner.env
Environment=DATA_DIR=/var/lib/twitch-miner
DynamicUser=yes
StateDirectory=twitch-miner
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now twitch-miner
```

systemd crea `/var/lib/twitch-miner` per i dati ed esegue il server con un suo utente
dedicato, mai come root. Apri `http://<indirizzo del server>:8080`; i log sono in
`journalctl -u twitch-miner`.

Questo file non si aggiorna da solo. Quando la dashboard segnala una nuova versione,
scarica il nuovo file dalla release, poi sostituisci quello vecchio e riavvia:

```bash
# ARM64: twitch-miner-server_<versione>_linux_arm64
sudo install -m 755 twitch-miner-server_<versione>_linux_x64 /usr/local/bin/twitch-miner
sudo systemctl restart twitch-miner
```

## <a name="how-it-works"></a>Come funziona

Ogni 20 secondi, ogni account sceglie i suoi due canali: il miglior canale in diretta per
la prima campagna della sua coda, poi gli streamer della sua lista dei punti. Una campagna
senza canale in diretta viene saltata a favore della successiva che ne ha uno («Nessun
canale in diretta» nella sua coda); i canali in diretta vengono ricontrollati ogni 90
secondi e l'account vi torna appena uno dei suoi streamer va in diretta.

Twitch accredita **una campagna Drops** e **due canali per i punti** alla volta per
account. Da ottobre 2026, un drop si può riscattare solo se l'account editore è
collegato. Le campagne non collegate avanzano comunque, e la dashboard mostra il link per
collegarlo.

Se il progresso di Twitch sulla prima campagna non si muove dopo 30 minuti di visione
reale, non la sta accreditando: l'account la mette da parte, la campagna successiva in
ordine prende il posto, e viene ritentata automaticamente 6 ore dopo — prima se nel
frattempo riappare un progresso, anche se la campagna ritentata può ancora aspettare
dietro quella in corso di mining. Qualsiasi progresso azzera l'attesa, e questo vale per
ogni tipo di campagna (Drops, badge, missioni). Se Twitch accredita invece un'altra
campagna della stessa categoria e quella si conclude o viene riscattata, l'accantonamento
viene revocato subito, invece di attendere le 6 ore intere. Riavviare l'app o il server dimentica
ogni accantonamento: una campagna bloccata riparte semplicemente con 30 minuti nuovi.

L'elenco delle campagne arriva dal progetto [Drops Alerts](https://dropsalerts.com)
(aggiornato ogni 5 minuti), perché Twitch lo nasconde al client TV.

## <a name="faq"></a>Domande frequenti

### Rischi e Twitch

**Il mio account può essere bannato?**\
Nessuno può garantire di no. Questo progetto non è affiliato a Twitch, e automatizzare un
account può violarne i termini o le regole di una campagna. Il miner guarda al massimo due
canali per account, il limite di Twitch, senza scaricare alcun video. Sta a te decidere.

**Il video viene davvero guardato?**\
No, nessun video viene scaricato. Per i Drops, ogni 15 secondi il miner legge la playlist
della live alla qualità più bassa e chiede solo l'header di ogni nuovo segmento. Per i
punti, invia ogni minuto il segnale «minuto guardato» di Twitch. Ogni canale guardato
mostra quanti segmenti sono stati richiesti.

**Perché al massimo due canali?**\
È il limite di Twitch: accredita solo due canali guardati contemporaneamente per account,
e una sola campagna Drops alla volta. In modalità **Drops e punti**, un canale serve la
campagna e l'altro i tuoi streamer. L'impostazione «Un canale», in
**Impostazioni account**, è più discreta.

### Drops

**Una campagna non viene minata, o un drop non avanza.**\
Apri la pagina **Drops** dell'account. In «Ordine di mining», ogni campagna in attesa
spiega perché: «Nessun canale in diretta» o «In attesa (una campagna alla volta)». «Twitch
non la conta — nuovo tentativo …» significa che 30 minuti di visione reale non hanno
portato progressi dal lato di Twitch: la campagna viene messa da parte e ritentata
automaticamente nel tempo indicato, o prima se nel frattempo riappare un progresso. Una
campagna che non compare in quell'elenco è stata scartata: da «Cosa minare, in ordine»,
dall'impostazione «Quali campagne», da una regola della scheda **Esclusioni**, oppure
perché non può finire in tempo o perché tutte le ricompense che le restano richiedono un
abbonamento. Una ricompensa che richiede un abbonamento aspetta che tu ti abboni o regali
un abbonamento durante la campagna, su un canale della categoria (un abbonamento già
attivo, un abbonamento Prime o un rinnovo non contano), un badge da guardare ogni giorno
aspetta il giorno dopo, niente viene minato prima dell'inizio della sua campagna, e un
drop che ne segue un altro aspetta che il primo sia completato. In modalità **Solo
punti**, il miner non sceglie alcuna campagna. «Mina per prima», nei dettagli di una
campagna, la porta in cima; una campagna ignorata può tornare con «Mina di nuovo», nella
scheda **Esclusioni**. La scheda **Campagne** mostra gli stessi motivi nel gruppo
**Bloccate**.

**Devo collegare l'account editore?**\
Per riscattare, sì: da ottobre 2026 Twitch permette di riscattare un drop solo se
l'account editore è collegato. Per impostazione predefinita, una campagna non collegata
avanza comunque e il riscatto aspetta il collegamento. Il badge «Non collegato» lo
segnala, e «Collega l'account editore», nei dettagli della campagna, apre la pagina di
collegamento. Per minare solo le categorie collegate, scegli
«Solo categorie con l'account editore collegato».

### Installazione e dati

**App desktop o Docker?**\
L'app desktop mina finché il PC è acceso, con la sua icona nell'area di notifica, una
password facoltativa e gli aggiornamenti con un clic. Docker mina giorno e notte su una
macchina sempre accesa (VPS, NAS, Raspberry Pi); la apri in un browser, protetta da
`MINER_PASSWORD`. L'interfaccia è la stessa.

**Dove sono i miei dati?**\
Nella cartella dei dati: `~/.local/share/twitch-miner` su Linux,
`%APPDATA%\twitch-miner` su Windows,
`~/Library/Application Support/twitch-miner` su macOS, e il volume `/data`
con Docker. Sul desktop, **Impostazioni › Desktop** la apre con un clic. Contiene
`miner.db` (account, impostazioni, registro), `master.key` (la chiave delle sessioni,
quando non è impostata alcuna password dell'app) e i log.

**Come si aggiorna?**\
L'app desktop controlla se c'è una nuova versione all'avvio, poi ogni ora (si può cambiare
in **Impostazioni › Informazioni**), e può avvisarti quando ne trova una. Fai clic sul
badge «Aggiornamento», poi su «Installa e riavvia». Con Docker, la dashboard ti avvisa:
esegui `docker compose pull`, poi `docker compose up -d`. Senza Docker, la dashboard
avvisa allo stesso modo: vedi [Senza Docker](#systemd) per sostituire il file e
riavviare il servizio. L'app elenca le novità di ogni versione successiva alla tua, dalla
più recente; le note di ogni versione sono anche nella sua release su GitHub.

**Ho dimenticato la password dell'app.**\
Non si può recuperare: è proprio lei a cifrare le tue sessioni Twitch. Chiudi l'app,
elimina la cartella dei dati, poi aggiungi di nuovo i tuoi account; le loro impostazioni
vanno rifatte. Con Docker, la password della dashboard si cambia in `MINER_PASSWORD`, poi
`docker compose up -d`.

### Punti e previsioni

**Quanti punti all'ora?**\
Dipende da Twitch e da ogni canale. Il miner guadagna quello che Twitch dà a uno
spettatore: i punti per il tempo di visione, i forzieri bonus (circa uno ogni 15 minuti) e
il bonus della serie di visione. Un abbonamento moltiplica i punti, da ×1,2 a ×2 secondo
il livello, e con «Prima i canali abbonati», attivo per impostazione predefinita, quei
canali vengono prima del resto della tua lista. La pagina Home mostra i punti guadagnati,
e il Registro ogni guadagno.

**Le scommesse sono rischiose?**\
Sì, si possono perdere punti. Le previsioni sono disattivate per impostazione
predefinita, streamer per streamer. Scegli tu la strategia, quando scommettere, la
puntata (5% del saldo per impostazione predefinita, al massimo 50.000 punti), un saldo
minimo e, se vuoi, una condizione, come una quota di almeno 1,5. Tieni bassa la puntata.
Una puntata sotto i 10 punti non viene mai piazzata.

**Uno streamer non viene guardato.**\
Vengono guardati solo gli streamer attivi e in diretta, e solo su un canale libero: in
modalità **Drops e punti**, uno dei due serve la campagna in corso; in modalità
**Solo Drops**, nessuno streamer viene guardato; un account in pausa non guarda niente. I
posti seguono quest'ordine, mostrato come badge su ogni canale guardato: «Serie a
rischio», «Bonus serie», «Abbonato», poi «Ordine della lista». Sposta lo streamer più in alto
nella lista, oppure disattiva «Prima le serie di visione» e «Prima i canali abbonati».

## <a name="security"></a>Sicurezza

- I token sono sigillati con AES-256-GCM. La chiave è un file `master.key` casuale accanto
  al database (predefinito, niente da fare) oppure è derivata dalla password dell'app con
  Argon2id.
- La cartella dei dati e quella dei log sono private (`0700`): solo l'utente che esegue il
  miner può aprirle.
- La dashboard HTTP controlla la password in tempo costante e usa cookie HttpOnly e
  SameSite=Strict (`Secure`, con il prefisso `__Host-`, dietro HTTPS). Il server
  conserva solo uno SHA-256 di ogni sessione. Chiude una sessione dopo 30 giorni o al
  logout. Controlla la sessione prima di leggere qualsiasi corpo della richiesta e limita
  i corpi a 256 KiB.
- Dopo 5 password errate di fila dallo stesso indirizzo IP (modulo di accesso o bearer),
  quell'indirizzo deve attendere 30 secondi. Il server risponde `429` con `Retry-After`
  senza guardare la password. Inoltre ogni password errata impiega mezzo secondo a
  ricevere risposta.
  Oltre 30 password sbagliate in un minuto dallo stesso indirizzo di connessione, un proxy
  condiviso compreso, quell'indirizzo ha un solo tentativo ogni 2 secondi: indovinare
  diventa lento e nessuno resta bloccato.
- Fuori dalla tua rete, metti la dashboard dietro un reverse proxy HTTPS con
  `MINER_PUBLIC_URL` (vedi [Docker](#docker)).
- Il miner comunica solo con `twitch.tv`, `ttvnw.net`, `jtvnw.net`, `twitchcdn.net`,
  `dropsalerts.com` e con le destinazioni delle notifiche che configuri. L'app
  (desktop e Docker) controlla le nuove versioni e le loro note su `github.com` e
  `api.github.com`, e l'app desktop le
  scarica dalle release GitHub del progetto. Sono firmate: viene installata solo la
  versione mostrata.

## <a name="build"></a>Compilare dai sorgenti

**Prerequisiti:** Rust, Node.js e i
[prerequisiti di Tauri](https://v2.tauri.app/start/prerequisites/) per il tuo sistema.

```bash
npm ci
npm run build          # dashboard
cargo build --release -p miner-server   # server: target/release/twitch-miner
npm run bundle:linux   # pacchetti desktop (richiede le dipendenze Linux di Tauri)
```

Controlli del codice:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
npm run verify         # prettier, oxlint (con i tipi), svelte-check e il controllo i18n di inlang
```

I tipi TypeScript dell'interfaccia sono generati dai tipi Rust con
[ts-rs](https://github.com/Aleph-Alpha/ts-rs) in `ui/src/lib/bindings`. Dopo aver
modificato un tipo visibile all'interfaccia, esegui `npm run bindings`.
