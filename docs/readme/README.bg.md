<h1 align="center">Twitch Miner</h1>

<p align="center">
  <strong>Копае Twitch Drops, значки и точки на канала с колкото акаунта искате, без браузър и без отворен раздел с Twitch.</strong>
</p>

<p align="center">
  Настолно приложение за Linux, Windows и macOS или Docker образ със същото уеб табло, който да пуснете на домашен сървър или на Raspberry Pi. Всеки акаунт използва около 3 МБ памет и почти не натоварва процесора.
</p>

## <a name="download"></a>Изтегляне

Изтеглете файла за вашата система от
[последната версия](https://github.com/SunkwiBOT/twitch-miner/releases/latest).

| Система | Пакет |
|---|---|
| **Windows** · x64 | [Инсталатор](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_windows_x64-setup.exe) или [преносим изпълним файл](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_windows_x64_portable.exe) |
| **Windows** · ARM64 | [Инсталатор](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_windows_arm64-setup.exe) или [преносим изпълним файл](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_windows_arm64_portable.exe) |
| **macOS** 13 или по-нова · универсална: Intel и Apple Silicon | [Образ на диск](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_macos_universal.dmg) (`.dmg`) |
| **Linux** · x86-64 | [`.AppImage`](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.AppImage), [`.deb`](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.deb) (Debian, Ubuntu) или [`.rpm`](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.rpm) (Fedora, openSUSE) |
| **Linux** · ARM64 | [`.AppImage`](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_arm64.AppImage), [`.deb`](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_arm64.deb) (Debian, Ubuntu, Raspberry Pi OS) или [`.rpm`](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_arm64.rpm) (Fedora, openSUSE) |
| **Linux сървър** · x86-64 или ARM64 | Самият сървър, без Docker ([x86-64](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner-server_linux_x64) или [ARM64](https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner-server_linux_arm64)): вижте [Без Docker](#systemd) |

В Linux можете да инсталирате и от терминал. На ARM64 заменете `x64` с `arm64` в
командите.

Debian, Ubuntu, Raspberry Pi OS:

```bash
curl -LO https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.deb
sudo apt install ./twitch-miner_linux_x64.deb
```

Fedora, openSUSE:

```bash
curl -LO https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.rpm
sudo dnf install ./twitch-miner_linux_x64.rpm
# openSUSE: sudo zypper install ./twitch-miner_linux_x64.rpm
```

AppImage, на всяка дистрибуция:

```bash
curl -LO https://github.com/SunkwiBOT/twitch-miner/releases/latest/download/twitch-miner_linux_x64.AppImage
chmod +x twitch-miner_linux_x64.AppImage
./twitch-miner_linux_x64.AppImage
```

Същите команди обновяват вече инсталираното приложение: имената на файловете не се
променят.

Версията за macOS не е нотаризирана. Първия път отворете приложението: macOS го блокира.
След това отидете в **System Settings › Privacy & Security** и щракнете **Open Anyway**.

Обновленията са подписани. Приложението проверява за нова версия при стартиране, а след
това на всеки час (честотата се променя в **Настройки › Относно**). То никога не инсталира
версия само: инсталирате я с едно щракване – от съобщението, което се появява, или от
**Настройки › Относно**.

Данните се намират в папката с потребителски данни:

- Linux: `~/.local/share/twitch-miner`
- Windows: `%APPDATA%\twitch-miner`
- macOS: `~/Library/Application Support/twitch-miner`

## <a name="features"></a>Функции

### Акаунти и стриймъри

- **Колкото акаунта искате в едно приложение.** Всеки акаунт копае самостоятелно, в свой режим:
  **Drops и точки** (един канал за най-добрата кампания, другият за вашите стриймъри),
  **Само Drops** или **Само точки**.

  <img src="../media/bg/accounts-mining.avif" alt="Няколко акаунта копаят едновременно, на страницата „Начало“">

- **Съветник за всеки нов акаунт.** След като влезете, започнете от настройките по
  подразбиране или от тези на друг акаунт. Изберете режима, кампаниите и стриймърите,
  после „Започни копаенето“ или „Запази и стартирай по-късно“.

  <img src="../media/bg/account-setup.avif" alt="Съветникът за настройка на нов акаунт, стъпка по стъпка">

- **Една промяна, пренесена в други акаунти с едно щракване.** След като промените нещо
  в акаунт, съобщението за потвърждение предлага „Приложи към други акаунти“. Същата
  промяна се прави в отметнатите акаунти, а останалите им настройки не се променят.

  <img src="../media/bg/apply-to-accounts.avif" alt="Промяна, повторена в други акаунти чрез „Приложи към други акаунти“">

- **Добавяне на стриймър.** Той започва веднага с опциите по подразбиране: тези на
  приложението или тези, които сте избрали за този акаунт. Ако трябва, ги коригирайте на
  място: бонус сандъци, рейдове, моменти, серия гледания, чат, прогнози.

  <img src="../media/bg/streamer-add.avif" alt="Добавяне на стриймър чрез търсенето в Twitch, после неговите опции">

- **Редактиране на стриймър.** „Редактирай“ отваря опциите му: бонус сандъци, рейдове,
  моменти, серия гледания, чат, прогнози… Превключвател го включва или изключва, без да го
  маха от списъка.

  <img src="../media/bg/streamer-edit.avif" alt="Опциите на стриймър, отворени от неговия ред">

- **Редактиране на няколко стриймъри наведнъж.** Отметнете ги, после
  „Редактирай N избрани стриймъри“. Прилагат се само опциите, които промените. Опция,
  която се различава между тях, показва „Смесено“, а превключвателят ѝ става два бутона –
  „Да“ и „Не“. След това приложението предлага да ги направи опции по подразбиране за
  новите стриймъри.

  <img src="../media/bg/streamers-group-edit.avif" alt="Редактиране на няколко стриймъри с опции „Смесено“">

- **Импорт на стриймъри.** Поставете списък (до 500 имена) или вземете списъка на друг
  акаунт или каналите, които акаунтът следва. Списъкът се проверява, така че се добавят
  само съществуващи канали.
  Обновяванията на живо обхващат 46 стриймъра на акаунт: следващите в списъка нямат
  рейдове, моменти и прогнози.

  <img src="../media/bg/streamers-import.avif" alt="Импорт на стриймъри: поставен списък, друг акаунт, следвани канали">

- **Spam Points.** Разменете персонализирана награда на канал няколко пъти подред.
  Изберете канал от списъка си „Точки“ или който и да е канал, намерен с търсенето в
  Twitch: наградите му се показват с баланса на акаунта, прочитан наново на живо. Задайте
  броя (до 25, в рамките на баланса), после „Размяна“. Резултатът се показва в края на
  серията, а всяка серия има свой ред в Дневника.

  <img src="../media/bg/spam-points.avif" alt="Spam Points: избран канал, 10 × размяна на награда със съобщение, размените се появяват в чата на канала в Twitch, после редът в Дневника">

### Drops

- **Всички текущи кампании за Drops.** Всяка кампания има своя карта с подробности:
  награди, свързване на акаунта на издателя, „Копай с приоритет“. Списъкът идва от проекта
  [Drops Alerts](https://dropsalerts.com) и се опреснява на всеки 5 минути.

  <img src="../media/bg/drops-catalogue.avif" alt="Каталогът като календар, търсенето и подробностите за кампания">

- **Вашият ред на копаене.** Плъзнете кампаниите в желания ред. Новите сами намират
  мястото си: първо приоритетните ви категории, после кампаниите, които свършват най-скоро или
  на които остават най-малко минути. Изключвайте категории, думи, кампания или отделна награда
  и пропускайте кампаниите, които не могат да завършат навреме. „Копай с приоритет“
  в подробностите за кампания я слага най-отгоре.

  <img src="../media/bg/drops-order.avif" alt="Редът на копаене, приоритетните категории и изключенията">

- **Инвентар и „Вземи всички“.** Страницата „Инвентар“ подрежда наградите в „За вземане“,
  „В ход“ и „Взети“. Вземайте ги една по една, всички наведнъж или включете
  „Вземай drops автоматично“.
  След „Свържи акаунта на издателя“ акаунтът се прочита отново, щом се върнете в приложението,
  и връзката се показва веднага.

  <img src="../media/bg/drops-inventory.avif" alt="Инвентарът и бутонът „Вземи всички“">

- **„Първо моите стриймъри за Drops и значки“.** За текущата кампания стриймър от вашия списък,
  чийто стрийм се зачита за тази кампания, минава преди другите канали. Същият канал
  придвижва drop-а напред и ви носи своите точки на канала. Включено по подразбиране.

  <img src="../media/bg/drops-streamers-first.avif" alt="Стриймър от списъка, гледан заради Drops и заради точките му">

- **Приоритет на наградите.** Когато две кампании са наравно в реда, майнерът първо избира
  тази, чиито награди съвпадат с предпочитания от вас вид (значка, емоция, предмет от
  играта). Той никога не променя вашия ред на майнинг.

- **Значки (бета).** Страницата „Значки“ изброява всички глобални значки в чата на Twitch
  и как се получават. Всеки акаунт има своя страница „Значки“: значките в ход с напредъка
  им, тези, които още може да получи, и тези, които притежава. Майнерът търси значките от
  кампании за Drops и куестове на Twitch и пропуска тези, които акаунтът вече има. Значка,
  която трябва да се гледа всеки ден, се копае отново всеки ден до последния („20 мин на
  ден, 3 дни“), и се брои канал от която и да е категория на кампанията. Сандък дава „1
  случайна значка от N“. Значка, която изисква абонамент, се копае, след като сте се
  абонирали или сте подарили абонамент по време на кампанията, в канал от категорията, и
  Twitch го е отчел. Вече действащ абонамент, абонамент с Prime или подновяване не се
  броят. Нищо не се копае преди началото на кампанията. В „Какво да се копае, по ред“
  подредете с плъзгане приоритетните категории, значките и другите кампании за Drops в
  желания ред или изключете някоя от тях. Куест на Twitch се копае само в канал, където
  Twitch го предлага в своя панел Drops. Еволюция (Pichu → Pikachu) се копае, щом акаунтът
  притежава значката, от която тя произлиза: майнерът сам слага тази значка точно преди
  това и не връща старата; „Копаене на еволюции на значки“ в настройките за значки на
  акаунта изключва това. Щракване върху значка отваря подробностите ѝ: цялото изискване,
  всички категории и канали, колекцията, еволюцията и напредъка на всеки акаунт. Тази
  функция е в бета версия.

  <img src="../media/bg/badges.avif" alt="Страницата „Значки“, значките на един акаунт, после „Какво да се копае, по ред“ със значките, плъзнати най-отпред">

### Проследяване

- **Дневник на всичко и всяка заявка.** Дневникът пази всяко събитие: drops, спечелени
  и похарчени точки, сандъци, залози, рейдове, започнали стриймове… Филтрирайте го по
  акаунт, раздел (Drops, Значки, Точки, Други) и тип. **Технически логове › Заявки** изброява всяка
  заявка, изпратена до Twitch и други услуги, с резултата и продължителността ѝ. Логовете
  и заявките не съдържат токени или тайни: „Копирай за доклад за бъг“ ги копира, готови за
  поставяне в доклад за бъг в
  [GitHub](https://github.com/SunkwiBOT/twitch-miner/issues) или
  [Discord](https://discord.gg/support-bots-891685895781113886).

  <img src="../media/bg/journal-requests.avif" alt="Филтрираният Дневник, после Технически логове › Заявки">

- **Страница Статистика.** Спечелени точки, взети drops, гледано време и спечелени
  прогнози за 7, 30 или 90 дни, с водещия стриймър или категория зад всяко число. Крива
  на точките за стриймър показва баланса във времето, с маркери за серии гледания,
  рейдове, моменти и прогнози, и подсказка на всеки от тях.

  <img src="../media/bg/stats.avif" alt="Плочките на Статистика за 30 дни, после крива на точките на стриймър с маркер">

- **Пауза и дневна пауза.** Един бутон за пауза, за един акаунт или за всички: пауза,
  докато не продължите, или за 30 минути, 1 час, 4 часа, до утре в 09:00 или до
  персонализирана дата и час; докато е на пауза, същият бутон показва „Продължи“. Значка
  показва кога свършва пауза с таймер, а всеки акаунт в страничната лента показва
  състоянието си: работи, на пауза или проблем, който трябва да се провери. Дневната
  пауза спира майнинга на всички акаунти всеки ден между два часа, в избраната часова
  зона, и го продължава след края ѝ, със собствена значка в горната лента.
- **Експортиране в CSV и брой по категория.** Дневникът експортира взетите drops като CSV
  файл (дата, акаунт, категория, кампания, drop, минути), филтрирани по акаунт, а прозорец
  показва колко drops са взети във всяка категория. Настолното приложение записва файла
  чрез прозорец за запис; уеб таблото го изтегля.

### На компютъра или на сървър

- **Един и същ интерфейс навсякъде.** Настолното приложение (Linux, Windows, macOS)
  и Docker образът показват едно и също табло. Docker работи на VPS, NAS или Raspberry Pi,
  без екран и браузър на тази машина: таблото се отваря във всеки браузър.
  На телефон таблото се нагажда към екрана, а през HTTPS се инсталира като приложение.
- **Лек.** Около 3 МБ памет на акаунт, почти никакво натоварване на процесора и Docker
  образ от около 12 МБ.

### Сигурност и обновления

- **Вашите сесии са защитени.** Без парола за Twitch: влизате на `twitch.tv/activate` от
  браузъра си. Сесиите са криптирани на диска и можете да ги отмените в

## <a name="docker"></a>Docker

Сървърът показва същото табло в браузър. Образът е
`ghcr.io/sunkwibot/twitch-miner`, за `amd64` и `arm64`. Когато излезе нова
версия, таблото ви съобщава: `docker compose pull`, след това `docker compose up -d`.

```yaml
services:
  miner:
    image: ghcr.io/sunkwibot/twitch-miner:latest
    pull_policy: always   # изтегля най-новия образ при всяко стартиране
    restart: unless-stopped
    ports: ["8080:8080"]   # зад обратно HTTPS прокси: премахнете или сменете с "127.0.0.1:8080:8080"
    environment:
      MINER_PASSWORD: "change-me"   # задължителна, поне 12 знака
      # MINER_PUBLIC_URL: "https://miner.example.com"   # само зад обратно HTTPS прокси
    volumes:
      - miner-data:/data

volumes:
  miner-data:
```

```bash
docker compose up -d
```

Отворете <http://localhost:8080> (или адреса на машината във вашата мрежа) и въведете
паролата.

### Променливи

| Променлива | По подразбиране | Предназначение |
|---|---|---|
| `MINER_PASSWORD` | няма | Парола за таблото, задължителна: без нея сървърът отказва да стартира. Поне 12 знака (при по-кратка се показва предупреждение при стартиране). Примерната стойност `change-me` се отказва. |
| `MINER_PASSWORD_FILE` | няма | Чете `MINER_PASSWORD` от файл, например Docker secret. Задайте едната или другата, не и двете. |
| `MINER_PUBLIC_URL` | няма | Само зад обратно HTTPS прокси (Caddy, nginx, Traefik, Cloudflare Tunnel…): адресът `https://` на таблото, без път, например `https://miner.example.com`. Проксито трябва да препраща `X-Forwarded-Proto`, `X-Forwarded-For` и websocket връзките, което обичайните проксита правят по подразбиране, а портът на контейнера не трябва да е достъпен директно. Тогава таблото отказва всичко, което не идва през проксито по HTTPS, и блокира адрес за 30 секунди след 5 грешни пароли. Проксито трябва да работи на същата машина или в локалната ѝ мрежа: връзка от публичен адрес се отказва. |
| `MINER_TRUSTED_HOPS` | `1` | Само заедно с `MINER_PUBLIC_URL`: колко проксита добавят запис в `X-Forwarded-For`, от 1 до 10. `2` при две проксита едно зад друго, например Cloudflare пред Traefik. |
| `MINER_PROXY_NETWORKS` | няма | Само с `MINER_PUBLIC_URL`: мрежите, от които се свързва проксито, разделени със запетаи, интервали или нови редове: един адрес или мрежа като `192.168.1.0/24` или `2001:db8:1::/64`. След като е зададена, проксито се приема само от loopback адреса и от тези мрежи, вече не от цялата частна локална мрежа. Празна стойност, `/0` или мрежа с установени битове на хоста спират стартирането само когато е зададен и `MINER_AUTH_HEADER`; без него се приемат с предупреждение. |
| `MINER_AUTH_HEADER` | няма | Forward auth / SSO: името на хедър, който проксито задава на вписания потребител: `Remote-User` за Authelia, `X-authentik-username` за Authentik, `X-Auth-Request-User` за oauth2-proxy (с `--set-xauthrequest`). Заявка, допусната през проксито — от адрес в `MINER_PROXY_NETWORKS`, с `Host`, съвпадащ с `MINER_PUBLIC_URL` — с един непразен ред в този хедър се вписва без `MINER_PASSWORD`. Изисква `MINER_PUBLIC_URL` и изрично зададена `MINER_PROXY_NETWORKS`; само loopback никога не е достатъчен за това. Отказва хедър, който проксито, браузър или клиент вече пише (`X-Forwarded-*`, `Host`, `Cookie`, `Authorization`, `X-Real-IP`, `Forwarded`, `Via`, `User-Agent`, `Accept*`, `Sec-Fetch-*`, `Cache-Control`, `CF-Connecting-IP`, `Priority`, `Connection`, `Origin`, `Referer`, `X-Request-Id`, `Content-Type`…). |
| `MINER_AUTH_USERS` | няма | Само с `MINER_AUTH_HEADER`: стойностите на хедъра, на които е позволено да влизат, разделени със запетаи, интервали или нови редове, както `MINER_PROXY_NETWORKS`. Сравнението е чувствително към регистъра. Зададена, но празна стойност се отказва, както празна `MINER_PROXY_NETWORKS` при зададен хедър. Без нея всяка стойност, зададена от проксито, влиза — всеки вписан чрез SSO потребител е администратор — и сървърът предупреждава за това при стартиране; с нея сървърът записва броя на разпознатите стойности при стартиране. |
| `MINER_VAULT_PASSPHRASE` | няма | Само за папка с данни, копирана от настолното приложение със зададена парола за приложението: отключва я при стартиране. Сървър, създаден от нулата, никога не се нуждае от нея. |
| `MINER_VAULT_PASSPHRASE_FILE` | няма | Чете `MINER_VAULT_PASSPHRASE` от файл. Задайте едната или другата, не и двете. |
| `DATA_DIR` | `/data` в образа, иначе `data` в работната директория | База данни, файл с ключа и логове. |
| `LOG_DIR` | `$DATA_DIR/logs` | Лог файлове: по един на ден, пазят се последните 14. |
| `HOST` / `PORT` | `0.0.0.0` / `8080` | Адрес за слушане: IP адрес и порт от 1 до 65535. |
| `RUST_LOG` | `info,hyper=warn,reqwest=warn` | Ниво на логване. |

Сървърът прочита и проверява променливите веднъж, при стартиране. Невалидна стойност спира
сървъра със съобщение, вместо мълчаливо да се използва резервна стойност.

Зад обратно proxy задайте `MINER_PUBLIC_URL`: без нея първата заявка, която идва през
proxy, записва предупреждение в логовете, защото опитите за вход тогава се броят на
адреса на proxy, и грешните пароли на един посетител биха блокирали всички. Връзката на
живо изпраща ping на всеки 30 секунди, за да не я затвори proxy, когато нищо не се
случва. Когато Twitch или мрежата откажат, сървърът отговаря с `424`, никога с `502` или
`504`: зад Cloudflare виждате истинската грешка вместо страницата на Cloudflare.


#### Вписване през доверено proxy (forward auth / SSO)

_Налично от v1.16.0._

С едно общо вписване пред няколко самостоятелно хоствани приложения (Authelia, Authentik,
oauth2-proxy…) `MINER_AUTH_HEADER` прескача собствената парола на таблото: вписването в
проксито е достатъчно. Задайте и `MINER_AUTH_USERS` с позволените стойности, иначе всеки
SSO потребител се вписва като администратор. `MINER_PASSWORD` продължава да работи за
скриптове, които се вписват директно с `POST /api/auth`, но никога през браузър:
router-ът по-долу препраща всяка друга заявка през `forwardAuth`, затова браузър,
отварящ таблото, винаги се нуждае първо от работещо SSO. Втори router действа само
при `POST` и `DELETE` на `/api/auth` — вписването и излизането с парола — и сам
занулява хедъра, вместо да премахва `forwardAuth`: разширяване на това правило отвъд
този единствен път би пропуснало там и подправен от клиента хедър.

Проксито трябва да запази оригиналния `Host` на заявката непроменен на пътя към miner-а,
иначе `MINER_PUBLIC_URL` никога не съвпада с него и хедърът се игнорира мълчаливо, с
предупреждение в логовете при първия такъв случай: nginx изисква
`proxy_set_header Host $host;`, Apache — `ProxyPreserveHost On`. Traefik и Caddy го
запазват непроменен по подразбиране, не е нужно нищо да се добавя за тях.

Нито един от тези продукти не премахва хедър, изпратен от самия клиент: всеки маршрут от
проксито до miner-а се нуждае от собствено правило, което го презаписва (`forwardAuth` на
Traefik изтрива само хедърите, изброени в `authResponseHeaders`, а всеки друг клиентски
хедър препраща непроменен). Пускайте проксито и miner-а сами на собствена мрежа, със
статичен адрес за проксито, и никога не публикувайте порта на miner-а: всичко друго,
достигащо до него — друг контейнер, процес на хоста — би могло само да зададе хедъра.

Authelia зад Traefik, само двете на `miner-net`, препращащи вписания потребител в
`Remote-User`:

```yaml
networks:
  edge: {}          # тук говорят Traefik и Authelia
  miner-net:        # само Traefik и miner-ът са в тази мрежа
    ipam:
      config:
        - subnet: 10.10.0.0/29

services:
  traefik:
    # вашата обичайна настройка на Traefik: entrypoints, други мрежи, други приложения
    networks:
      edge: {}
      miner-net:
        ipv4_address: 10.10.0.2

  authelia:
    # вашата обичайна настройка на Authelia
    networks:
      edge: {}
    labels:
      traefik.http.middlewares.authelia.forwardAuth.address: "http://authelia:9091/api/authz/forward-auth"
      traefik.http.middlewares.authelia.forwardAuth.trustForwardHeader: "true"
      traefik.http.middlewares.authelia.forwardAuth.authResponseHeaders: "Remote-User"
      # за router-а на скриптовете по-долу: занулява Remote-User вместо да
      # пропуска проверката, така че подправен от клиента хедър пак не работи на този маршрут
      traefik.http.middlewares.blank-remote-user.headers.customrequestheaders.Remote-User: ""

  miner:
    image: ghcr.io/sunkwibot/twitch-miner:latest
    networks:
      miner-net:
        ipv4_address: 10.10.0.3   # също статичен: произволно избран адрес би могъл да съвпадне
    # без "ports": тази мрежа достига само до Traefik, от 10.10.0.2
    environment:
      MINER_PASSWORD: "change-me"
      MINER_PUBLIC_URL: "https://miner.example.com"
      MINER_PROXY_NETWORKS: "10.10.0.2"
      MINER_AUTH_HEADER: "Remote-User"
      MINER_AUTH_USERS: "alice,bob"
    volumes:
      - miner-data:/data
    labels:
      traefik.http.routers.miner.rule: "Host(`miner.example.com`)"
      traefik.http.routers.miner.middlewares: "authelia@docker" # повторете за всеки router към miner-а
      # за скриптовете, с MINER_PASSWORD: заобикаля Authelia, но не и занулването на хедъра
      traefik.http.routers.miner-api.rule: "Host(`miner.example.com`) && Path(`/api/auth`) && (Method(`POST`) || Method(`DELETE`))"
      traefik.http.routers.miner-api.middlewares: "blank-remote-user@docker"

volumes:
  miner-data:
```

#### Усилване на друго proxy

Нито един от тези продукти сам не премахва копие от хедъра, изпратено от клиента:
добавете реда за премахване по-долу преди директивата, която го задава от отговора на
SSO, на всеки маршрут към miner-а, включително този за скриптовете. Traefik, Caddy,
nginx, Apache и HAProxy по-долу бяха всеки проверени на реален инстанс, прекратяващ
TLS, с подправен хедър, удвоен хедър и вариант с регистър или долна черта; Cloudflare
Tunnel и Tailscale Serve идват от собствената им документация и изходен код,
непроверени самостоятелно тук.

- **nginx**: `auth_request` само валидира, сам никога не пипа хедъри — конфигурация,
  която го извиква, но никога сама не задава `Remote-User`, препраща реда на клиента
  непроменен (доказано: подправен `Remote-User: admin` достигна miner-а буквално
  без следващите два реда). Винаги добавяйте
  `auth_request_set $auth_user $upstream_http_remote_user;`, а след това
  `proxy_set_header Remote-User $auth_user;`, която го презаписва — никога
  незадължително. Също `proxy_set_header Host $host;`, или `$http_host`, ако
  `MINER_PUBLIC_URL` сочи нестандартен порт (`$host` премахва порта, и на хедъра
  тогава никога не се доверява мълчаливо). nginx също изхвърля всеки хедър, чието
  име съдържа долна черта, освен ако не е зададено `underscores_in_headers on;`;
  затова `MINER_AUTH_HEADER` отказва такова име.
- **Caddy**: `forward_auth` с `copy_headers Remote-User` вече сам презаписва копие
  от клиента, доказано, нищо друго не е нужно. `request_header -Remote-User` точно
  преди него е допълнителна безвредна дълбока защита, не изискване, за разлика от
  Traefik, където втори router, който изцяло пропуска `forwardAuth`, наистина се
  нуждае от изричното занулаване.
- **Apache**: `RequestHeader unset Remote-User` безусловно, после
  `RequestHeader set Remote-User "…" env=AUTH_OK` въз основа на това, което
  проверява сесията, и `ProxyPreserveHost On` заради същото изискване за `Host`
  както по-горе.
- **HAProxy**: `http-request del-header Remote-User` безусловно, после
  `http-request set-header Remote-User alice if <acl-валидна-сесия>`. HAProxy също
  сам никога не пипа `X-Forwarded-For`: добавете
  `http-request set-header X-Forwarded-For %[src]`, иначе подправена стойност
  достига miner-а непроменена.
- **Cloudflare Tunnel**: оставете `httpHostHeader` незададен (по подразбиране вече
  препраща публичния `Host`, поискан от клиента); това е тунел, а не proxy, който
  изчиства хедъри, затова го комбинирайте с едно от proxy-тата по-горе за
  `MINER_AUTH_HEADER`, вместо да му се доверявате само на него.
- **Tailscale Serve**: `Tailscale-User-Login`. `tailscaled` вече премахва всяко копие,
  изпратено от клиента, преди да зададе своето, няма какво сами да изчиствате; важно е
  само до miner-а да може да достигне единствено `tailscale serve`, никога директна
  връзка — свържете го с `127.0.0.1` и оставете само Serve да посредничи.

Какъвто и proxy да изберете, тествайте го веднъж, преди да му се доверите: след изход от
SSO, направете `curl` директно към адреса на самия miner (заобикаляйки проксито, от
машината или контейнера, на който работи) с хедър, зададен ръчно, като
`curl -H "Remote-User: mallory" http://127.0.0.1:8080/api/snapshot`; трябва да отговори
с `401`, никога със снимката на състоянието.

### <a name="systemd"></a>Без Docker (systemd)

На Linux сървър без Docker изданието съдържа сървъра и като единичен файл, с таблото
вътре: `twitch-miner-server_<версия>_linux_x64` или
`twitch-miner-server_<версия>_linux_arm64`. Това е същата програма, която изпълнява
Docker образът, статично линкована: нищо друго не е нужно за инсталиране, освен
системните CA сертификати, които чете за HTTPS (Docker образът ги копира по същата
причина). Приема същите променливи.

```bash
# ARM64: twitch-miner-server_<версия>_linux_arm64
sudo install -m 755 twitch-miner-server_<версия>_linux_x64 /usr/local/bin/twitch-miner
sudo install -m 600 /dev/null /etc/twitch-miner.env
```

Запишете собствена парола, поне 12 знака, в `/etc/twitch-miner.env`, която само root
може да чете:

```ini
MINER_PASSWORD=change-me
```

После услугата, в `/etc/systemd/system/twitch-miner.service`:

```ini
[Unit]
Description=Twitch Miner
Wants=network-online.target
After=network-online.target

[Service]
ExecStart=/usr/local/bin/twitch-miner
EnvironmentFile=/etc/twitch-miner.env
Environment=DATA_DIR=/var/lib/twitch-miner
DynamicUser=yes
StateDirectory=twitch-miner
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now twitch-miner
```

systemd създава `/var/lib/twitch-miner` за данните и изпълнява сървъра под собствен
потребител, никога като root. Отворете `http://<адрес на сървъра>:8080`; логовете са в
`journalctl -u twitch-miner`.

Този файл не се обновява сам. Когато таблото покаже нова версия, изтеглете новия файл от
изданието, после заменете стария и рестартирайте:

```bash
# ARM64: twitch-miner-server_<версия>_linux_arm64
sudo install -m 755 twitch-miner-server_<версия>_linux_x64 /usr/local/bin/twitch-miner
sudo systemctl restart twitch-miner
```

## <a name="how-it-works"></a>Как работи

На всеки 20 секунди всеки акаунт избира двата си канала: най-добрия канал на живо за
първата кампания в опашката си, след това стриймърите от списъка си за точки. Кампания
без канал на живо се прескача в полза на следващата, която има такъв („Няма канал на
живо“ в опашката ѝ); каналите на живо се проверяват отново на всеки 90 секунди, а
акаунтът се връща към нея веднага щом някой от стриймърите му излезе на живо.

Twitch зачита **една кампания за Drops** и **два канала за точки** едновременно на акаунт.
От октомври 2026 г. drop може да се вземе само когато акаунтът на издателя е свързан.
Несвързаните кампании пак напредват, а таблото показва линка за свързване.

Ако Twitch не придвижи напредъка по първата кампания след 30 минути реално гледане, той
не я зачита: акаунтът я оставя настрана, следващата по ред кампания заема мястото ѝ и
опитът се повтаря автоматично 6 часа по-късно — по-рано, ако напредъкът се появи отново,
макар повторената кампания пак да може да изчака зад тази, която в момента се копае.
Всеки напредък нулира изчакването и то важи за всички видове кампании (Drops, значки,
куестове). Ако Twitch вместо това зачете друга кампания от същата категория и тя приключи или бъде взета, отлагането се вдига веднага, вместо да чака пълните 6 часа. Рестартирането на приложението или сървъра забравя всички отложени кампании:
заседнала кампания просто получава нови 30 минути.

Списъкът с кампании идва от проекта [Drops Alerts](https://dropsalerts.com)
(опреснява се на всеки 5 минути), защото Twitch го крие от TV клиента.

## <a name="faq"></a>Често задавани въпроси

### Рискове и Twitch

**Може ли акаунтът ми да бъде блокиран?**\
Никой не може да обещае, че няма. Този проект не е свързан с Twitch, а автоматизирането на
акаунт може да наруши условията му или правилата на дадена кампания. Майнерът гледа
най-много два канала на акаунт – ограничението на Twitch – и не изтегля видео. Решението
е ваше.

**Наистина ли се гледа видеото?**\
Не, не се изтегля никакво видео. За Drops майнерът на всеки 15 секунди чете плейлистата на
стрийма в най-ниското качество и изисква само хедъра на всеки нов сегмент. За точките
изпраща всяка минута сигнала на Twitch „изгледана минута“. При всеки гледан канал се вижда
колко сегмента са изискани.

**Защо най-много два канала?**\
Това е ограничението на Twitch: зачита само два едновременно гледани канала на акаунт
и само една кампания за Drops наведнъж. В режим **Drops и точки** единият канал служи на
кампанията, а другият – на вашите стриймъри. Настройката „Един канал“ в
**Настройки на акаунта** е по-дискретна.

### Drops

**Кампания не се копае или drop не напредва.**\
Отворете страницата **Drops** на акаунта. В „Ред на копаене“ всяка чакаща кампания казва
защо: „Няма канал на живо“ или „Изчаква (по една кампания)“. „Twitch не брои — нов опит …“
означава, че 30 минути реално гледане не са донесли напредък от страна на Twitch:
кампанията се оставя настрана и се опитва отново автоматично след показаното време, или
по-рано, ако напредъкът се появи отново. Кампания, която не се появява в този списък, е
отпаднала: заради „Какво да се копае, по ред“, заради настройката „Кои кампании“, заради
правило в раздела **Изключения**, защото не може да завърши навреме или защото всички
оставащи награди изискват абонамент. Награда, която изисква абонамент, изчаква да се
абонирате или да подарите абонамент по време на кампанията, в канал от категорията (вече
действащ абонамент, абонамент с Prime или подновяване не се броят), значка, която трябва
да се гледа всеки ден, изчаква следващия ден, нищо не се копае преди началото на
кампанията, а drop, който следва друг, изчаква първия да завърши. В режим **Само точки**
майнерът не избира кампания. „Копай с приоритет“ в подробностите за кампания я слага
най-отгоре; игнорирана кампания може да се върне с „Копай отново“ в раздела
**Изключения**. Разделът **Кампании** в групата **Блокирани** показва същите причини.

**Трябва ли да свържа акаунта на издателя?**\
За да вземете drop – да: от октомври 2026 г. Twitch позволява да вземете drop само когато
акаунтът на издателя е свързан. По подразбиране несвързаната кампания пак напредва, а вземането
изчаква свързването. Значката „Несвързан“ показва това, а „Свържи акаунта на издателя“
в подробностите за кампанията отваря страницата за свързване. За да копаете само свързани
категории, изберете „Само категории със свързан акаунт на издателя“.

### Инсталиране и данни

**Настолно приложение или Docker?**\
Настолното приложение копае, докато компютърът ви е включен, с икона в системната област,
парола по избор и обновления с едно щракване. Docker копае денонощно на машина, която
е винаги включена (VPS, NAS, Raspberry Pi); отваряте го в браузър, защитен с
`MINER_PASSWORD`. Интерфейсът е същият.

**Къде са данните ми?**\
В папката с данни: `~/.local/share/twitch-miner` в Linux,
`%APPDATA%\twitch-miner` в Windows,
`~/Library/Application Support/twitch-miner` в macOS и томът `/data` при
Docker. На компютъра **Настройки › Работен плот** я отваря с едно щракване. Там са
`miner.db` (акаунти, настройки, дневник), `master.key` (ключът за сесиите, когато не
е зададена парола за приложението) и логовете.

**Как да обновя?**\
Настолното приложение проверява за нова версия при стартиране, а след това на всеки час
(може да се промени в **Настройки › Относно**), и може да ви уведоми, когато намери такава.
Щракнете върху значката „Обновление“, после върху „Инсталирай и рестартирай“. При Docker
таблото ви съобщава: изпълнете `docker compose pull`, после `docker compose up -d`. Без
Docker таблото ви съобщава по същия начин: вижте [Без Docker](#systemd), за да замените
файла и рестартирате услугата. Приложението изброява промените във всяка версия след
вашата, от най-новата към най-старата; бележките на всяка версия са и в изданието ѝ в GitHub.

**Забравих паролата за приложението.**\
Тя не може да бъде възстановена: именно тя криптира Twitch сесиите ви. Затворете
приложението, изтрийте папката с данни и добавете акаунтите си отново; настройките им
трябва да се зададат наново. При Docker паролата за таблото се сменя в `MINER_PASSWORD`,
след което се изпълнява `docker compose up -d`.

### Точки и прогнози

**Колко точки на час?**\
Зависи от Twitch и от всеки канал. Майнерът получава това, което Twitch дава на зрител:
точки за гледане, бонус сандъци (около един на всеки 15 минути) и бонуса за серия
гледания. Абонаментът умножава точките – от ×1,2 до ×2 според нивото, а с „Първо
абонираните канали“, включено по подразбиране, тези канали минават преди останалата част
от списъка ви. Страницата „Начало“ показва спечелените точки, а Дневникът – всяка печалба.

**Рисковани ли са залозите?**\
Да, може да загубите точки. Прогнозите са изключени по подразбиране, за всеки стриймър
поотделно. Вие задавате стратегията, момента на залога, залога (по подразбиране 5% от
баланса, най-много 50 000 точки), минимален баланс и, ако искате, условие, например
коефициент поне 1,5. Залагайте малко.
Залог под 10 точки никога не се прави.

**Стриймър не се гледа.**\
Гледат се само включени стриймъри на живо и само на свободен канал: в режим
**Drops и точки** единият от двата служи на текущата кампания; в режим **Само Drops** не се
гледа никой стриймър; акаунт на пауза не гледа нищо. Местата се разпределят в този ред,
показан като значка на всеки гледан канал: „Серията е застрашена“, „Бонус за серия“,
„Абониран“, после „Ред в списъка“. Преместете стриймъра по-нагоре в списъка или изключете
„Първо сериите гледания“ и „Първо абонираните канали“.

## <a name="security"></a>Сигурност

- Токените са запечатани с AES-256-GCM. Ключът е или случаен `master.key` до базата данни
  (по подразбиране, без намеса), или е изведен от паролата за приложението с Argon2id.
- Папката с данни и папката с логове са лични (`0700`): само потребителят, който
  стартира майнера, може да ги отвори.
- HTTP таблото проверява паролата за постоянно време и използва бисквитки HttpOnly,
  SameSite=Strict (`Secure`, с префикса `__Host-`, зад HTTPS). Сървърът пази само
  SHA-256 на всяка сесия. Той прекратява сесия след 30 дни или при изход. Проверява
  сесията, преди да прочете което и да е тяло на заявка, и ограничава телата до 256 KiB.
- След 5 поредни грешни пароли от един IP адрес (формуляр за вход или bearer) този адрес
  изчаква 30 секунди. Сървърът отговаря с `429` и `Retry-After`, без да поглежда паролата.
  Освен това отговорът на всяка грешна парола отнема половин секунда.
  След 30 грешни пароли за минута от един адрес на връзка, включително споделено прокси,
  този адрес получава по един опит на всеки 2 секунди: отгатването се забавя, а никой не
  бива блокиран.
- Извън вашата мрежа поставете таблото зад обратно HTTPS прокси с `MINER_PUBLIC_URL`
  (вижте [Docker](#docker)).
- Майнерът комуникира само с `twitch.tv`, `ttvnw.net`, `jtvnw.net`, `twitchcdn.net`,
  `dropsalerts.com` и целите за известия, които сте настроили. Приложението
  (настолно и Docker) проверява за нови версии и бележките им в `github.com` и
  `api.github.com`, а настолното приложение ги
  изтегля от GitHub releases на проекта. Те са подписани: инсталира се само показаната
  версия.

## <a name="build"></a>Компилиране от изходния код

**Предварителни изисквания:** Rust, Node.js и
[предварителните изисквания на Tauri](https://v2.tauri.app/start/prerequisites/) за вашата
система.

```bash
npm ci
npm run build          # табло
cargo build --release -p miner-server   # сървър: target/release/twitch-miner
npm run bundle:linux   # настолни пакети (изискват Linux зависимостите на Tauri)
```

Проверки на кода:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
npm run verify         # prettier, oxlint (с проверка на типовете), svelte-check и проверката за i18n на inlang
```

TypeScript типовете на интерфейса се генерират от Rust типовете с
[ts-rs](https://github.com/Aleph-Alpha/ts-rs) в `ui/src/lib/bindings`. След промяна на
тип, който интерфейсът вижда, изпълнете `npm run bindings`.
